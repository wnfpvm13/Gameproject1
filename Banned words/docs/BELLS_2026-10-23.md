# 미니게임 개편 6b — 의자 벨·발언권·좋아하는 거 말하기·벨 퀴즈: 만든 기록 (2026-10-23)

후임 에이전트용 기록이다. 규칙은 `docs/DESIGN_V3.md` 5.1(벨·발언권)·5.2(1번 벨 퀴즈, 9번 좋아하는 거 말하기)·7번(발언권 동안의 채팅)·8번(진행자 판정)·9번(맵 계약 `Bell`)이 기준이다. 바로 앞 묶음은 `docs/MINIGAME_FLOW_2026-10-23.md`(6a, 태그 `banned-words-v3-6a`).

## 오너 결정 (2026-10-23)

- 의자마다 벨, 앉은 참가자가 E(폰은 터치)로 누른다. 퀴즈·좋아하는 거 말하기에서 누른 사람이 말할 기회를 갖는다.
- 벨 퀴즈는 벨 1등이 **말로** 답하고 진행자가 판정한다(작성자 추천은 버튼 답). 그래서 진행자가 있을 때만 나온다.

## 무엇이 들어갔나

- **맵(`tools/build_pool_hall.luau`):** 의자마다 `Bell` 모델(앉은 사람 오른쪽 = 의자 로컬 +X, 의자 사이 틈 가운데, 높이 2.2스터드의 기둥 + 받침 + 금색 돔 `Light`(PointLight, 평소 꺼짐) + 빨간 `Button`(PrimaryPart)). 부딪치지 않는 장식(TRIM)이라 발사에 영향이 없다.
- **벨(`server/services/BellService`, 새):** 미션이 몇 명의 벨을 정해진 시간 동안 연다(`collect`). 한 번 열릴 때 한 사람 한 번, 서버에 도착한 순서로 기록한다(핑 영향은 알고 넘어감). 생존·본 경기·날아가는 중 아님·`BELL_COOLDOWN`(0.2초)을 검사하고, 열려 있지 않을 때 누른 것은 무시한다. 열림·닫힘은 `BellOpen`(`{ open, ids, endsAt }`), 울림은 `BellRang`(`{ userId }`)으로 모두에게 보낸다. 리모트 `Bell`(클라이언트 → 서버, 인자 없음).
- **발언권:** RoundService의 `setFloor(player?)`가 `VoiceService.setFloor({ 발언권자, 진행자 })`(그 둘만 모두에게 들리고, 다른 생존자는 아무에게도 안 들림, 탈락자·관전자 그룹과 채팅 참가자 음소거는 그대로)와 `ChatGate.setFloor(player)`(생존자는 발언권자의 글만 받음, 진행자는 모두 받음)를 함께 정한다. 미션이 끝날 때마다, 판 정리 때 항상 풀고 벨도 닫는다.
- **미션 ctx(`MissionRunner`):** `bell(from, seconds, firstOnly)`(누른 사람 순서), `floor(player?)`, `presenterVerdict(answer, seconds)`("right"/"wrong"/nil), `score(player, amount)`. 진행자 판정은 `PresenterService.ask("verdict", { ⭕ 맞음, ❌ 틀림 }, seconds, stop, note = 정답)` — 시간을 넘기면 진행자 넘김으로 센다.
- **좋아하는 거 말하기(`missions/OneWord`, 옛 "모두에게 한마디"):** 먼저 땅에 있는 모두의 벨을 `BELL_ORDER_SECONDS`(5초) 연다. 공연자는 이번 판에 덜 한 사람 먼저, 같으면 먼저 누른 순서, 그다음 무작위로 최대 5명. 각자 말하는 동안 발언권을 갖는다. 진행자가 없어도 생존자가 `VOTE_MIN_VOTERS`(4) 이상이면 나온다(투표로 정함). 이름은 "좋아하는 거 말하기".
- **벨 퀴즈(`missions/Quiz`의 `Quiz.bell`, 새):** 퀴즈와 같은 파일에 두어 문제은행·"다시 안 내기"를 같이 쓴다. `BELL_QUIZ_QUESTIONS`(3)문제. 문제마다 땅에 있는 사람(이번 문제에 이미 답한 사람 제외)의 벨을 `BELL_WAIT_SECONDS`(8초) 열고 첫 벨에서 닫는다. 1등이 발언권을 갖고, 진행자는 `BELL_ANSWER_SECONDS`(5초, 채팅 참가자는 10초) + `BELL_VERDICT_SECONDS`(5초) 안에 맞음/틀림을 누른다(진행자 메뉴 제목에 정답이 보인다).
    - 맞음: 점수 +1(`SCORE_BELL_QUIZ`), 정답 공개, 다음 문제.
    - 틀림: 주관 판정 발사(공개 서버 한도에 걸린 사람은 안 날아감), 같은 문제의 벨을 다른 사람에게 다시 연다. 한 문제의 답 기회는 `BELL_TRIES`(3)번.
    - 판정 시간 초과: 벌칙 없이 다음 벨.
    - 처음부터 아무도 안 누르면 그 문제는 전원 4지선다(퀴즈와 같음). 진행자가 중간에 없어지면 남은 문제를 전원 4지선다로 낸다.
- **화면:**
    - `client/Bell`(새): 내가 앉은 의자의 벨 `Button`에만 ProximityPrompt(E·패드 X·터치, 거리 10)를 만들고, 서버가 내 벨을 열었을 때만 켠다. 다른 사람의 벨은 그 사람이 앉은 의자(`Seat.Occupant`)로 찾는다.
    - `client/UI/BellButton`(새): 화면 아래 큰 "🔔 벨" 버튼(폰을 위해). 한 번 누르면 다음에 열릴 때까지 숨긴다.
    - `client/Fx.bellRang`: 딩 소리 + 그 벨의 돔이 0.6초 빛남.
    - `client/UI/MissionPanel`: `oneWordBell`("🔔 벨을 누르면 먼저 말해요" + 남은 초), `bellQuiz`(문제 + "벨을 눌러 답하세요" / "○○ 님이 답하는 중").
    - `client/UI/PresenterPanel`: 메뉴 종류 `verdict`(제목 "맞았나요? 정답: ○○ · 남은 초", 누르면 바로 보냄).
- **설정(`shared/Config`):** `BELL_COOLDOWN` 0.2, `BELL_ORDER_SECONDS` 5, `BELL_QUIZ_QUESTIONS` 3, `BELL_WAIT_SECONDS` 8, `BELL_TRIES` 3, `BELL_ANSWER_SECONDS` 5, `BELL_ANSWER_CHAT_SECONDS` 10, `BELL_VERDICT_SECONDS` 5, `SCORE_BELL_QUIZ` 1, `SOUND_BELL`(지금은 APM "Correct Answer 2" — 짧은 탁상 벨 소리로 바꿀지 오너가 들어 보고 정함). 문구 `ONE_WORD_TITLE`·`ONE_WORD_START`·`ONE_WORD_BELL`·`BELL_*`·`VERDICT_*`.

## 교차검증 (Codex 1번 + Claude 검토자 1번)

- **Codex:** [P1] 진행자 메뉴에 번호가 없어 앞 판정 메뉴에서 늦게 누른 맞음/틀림이 다음 답하는 사람에게 적용될 수 있음. [P2] 벨 창 번호·마감 없음, 발언권 도중 진행자가 바뀌면 새 진행자 무음, 답하는 사람이 나가도 발언권이 남음, 진행자가 문제 도중 나가면 그 문제를 건너뜀, 벨 퀴즈 시간 예산이 짧음(168 → 실제 최대 216초), "덜 한 사람 우선"이 판마다 초기화되지 않음(서버 단위 누적), 재착석 뒤 E 프롬프트가 늦게 붙음. [P3] Sync가 이미 누른 벨 버튼을 다시 보임.
- **Claude 검토자:** P1 없음. [P2] 벨 퀴즈 시간 예산(같은 지적). P3: 진행자 교체 때 발언권, 답하는 사람 퇴장, 첫 누름 창이 바로 닫히지 않아 딩이 여러 번, 프롬프트 갱신, 진행자 중간 퇴장, 숫자 `minPlayers = 2`, 벨이 두 의자 사이 한가운데라 누구 것인지 헷갈림, 설계 문서의 ctx 표기.
- **반영:**
    - 진행자 메뉴마다 번호(`PresenterMenu.id`), 누름(`PresenterPick`)이 그 번호를 보내야 통함. 시험 15c(옛 번호 무시).
    - 벨 창마다 번호(`BellOpen.id`), 누름(`Bell`)이 그 번호를 보내야 통함; 첫 누름만 받는 창은 첫 누름 순간 닫음(딩 한 번). 시험 15a(옛 번호 무시).
    - RoundService가 발언권자를 기억해 진행자가 바뀌면 발언권을 다시 정함(새 진행자도 들림).
    - 진행자 판정은 답하는 사람이 나가거나 날아가면 바로 끝남(벌칙 없음, 발언권 풀림). 시험 15f.
    - 진행자가 문제 도중 없어지면 그 문제를 전원 4지선다로. 시험 7h.
    - 벨 퀴즈 시간 예산 = 문제 수 × (답 기회 × (벨 + 채팅 답 + 판정) + 정답 공개) = 216초. 시험 7i. 설계 문서 공식도 고침.
    - "덜 한 사람 우선"을 판마다 초기화.
    - 클라이언트: 앉거나 일어날 때(`Humanoid.Seated`) 다시 그려 프롬프트를 옮김, 같은 창이 다시 오면(Sync) 누른 상태 유지.
    - `BELL_QUIZ_MIN_PLAYERS`·`TALK_MIN_PLAYERS`를 Config로, 벨을 자기 의자 쪽으로(받침 가장자리에서 0.45스터드), 설계 문서 ctx 표기.
    - 작성자가 일부러 고장 내 확인(되돌림): 메뉴 번호·창 번호·답하는 사람 퇴장·진행자 중간 퇴장을 각각 되돌리면 15c·15a·15f·7h가 실패했다.

- **Codex 재확인(1번):** 메뉴 번호·발언권 진행자 교체·시간 예산·판마다 초기화·프롬프트 갱신·Sync 누름 유지는 고쳐짐. 덜 고쳐진 것: 벨 창 마감 직후 도착한 누름 통과, 판정 대기가 취소되는 순간의 누름이 먼저 반환됨, 마지막 답 기회의 판정 중 진행자 퇴장 때 4지선다로 안 넘어감. 모두 고쳤다(받을 때 `endsAt` 검사, `ask`가 결과보다 취소를 먼저 봄, 판정 직후 진행자 재확인). 규칙대로 재확인은 더 받지 않았다.
