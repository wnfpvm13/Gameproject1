# 묶음 12 — 미션 카드 위로, 퀴즈 답 머리 위 공개 (2026-10-27)

## 오너 요청과 답
- **요청:** "미션 때문에 캐릭터가 보이지 않아. 미션을 살짝 반투명하게 중앙 위쪽으로 올리고, 퀴즈의 경우 유저들이 채팅으로 답을 입력하면 (ex:1,2,3,4) 바로 채팅이 출력되지 않고 제한 시간이 모두 지나면 모두의 입력한 것을 확인시켜준 뒤 틀린 애만 날리게 바꾸는거지 / 입력창도 의자나 캐릭터를 가리면 안돼"
- **확인 질문에 대한 오너 답:**
  - 입력 방식: "카드를 좀 위로 올리고, 시간이 끝나고 각자의 머리 위에 어떤 선택했는지 나오고 날리면 되겠다"
  - 공개 방식: "각자 머리 위에"
  - 적용 범위: 4지선다 퀴즈(결승 포함), 초성 퀴즈, O/X 퀴즈, 숫자 근사 퀴즈 전부
- **답 입력:** 버튼(숫자 근사는 입력창)과 **채팅** 둘 다 된다. 처음에는 채팅 답을 빼고 만들었는데, Codex 검토가 "원래 요청의 채팅 입력·즉시 노출 금지는 철회되지 않았다"고 짚어 리뷰 수정에서 넣었다(아래 '검토 반영').

## 바뀐 것
- **미션 카드:**
  - 모든 미션 카드가 화면 위쪽 가운데, 상태판 아래(`Style.row(1)`)에 붙는다.
  - 배경은 30% 투명(`CARD_ALPHA`), 단추는 12% 투명이다.
  - 화면 높이의 60%(`CARD_ROOM`) 안에 들어가게 줄어든다. 아래쪽 40%는 의자와 캐릭터 자리다.
  - 숫자 근사의 입력창도 카드 안에 있어 같이 올라간다. 폰은 입력창을 누르면 Roblox 키보드가 아래에서 올라오는데, 이건 게임에서 막을 수 없다.
- **알림(토스트):** 카드가 보이는 동안 카드 바로 아래로 옮긴다(`Toast.place(MissionPanel.bottom())`). 카드가 없으면 원래 자리다.
- **4지선다 단추:** 번호가 붙는다("1. 광합성"). 머리 위 공개도 그 번호로 한다. O/X는 O·X 그대로다.
- **답 공개 순서:** 시간이 끝나면(모두 답하면 바로) 아래 순서로 간다.
  1. **`PICKS_SECONDS`(2초):** 모두의 답이 머리 위 노란 카드로 뜬다. 공개 문구는 "모두의 답 공개!"이고, 무응답은 "?"다. 이때는 정답도, 날아감도 없다. 카드 화면은 `quizResult`에 `answer` 없이 `picks`만 실려 온다.
  2. **정답 공개:** 머리 위 카드가 초록(맞음) 또는 빨강(틀림)으로 바뀌고, 틀린 사람이 바로 날아간다.
  3. **미션별 차이:**
     - O/X는 문장마다 공개하고, 날아가는 것은 지금처럼 3문장이 끝난 뒤 가장 많이 틀린 사람이다.
     - 숫자 근사는 모두의 숫자(천 단위 쉼표)를 보여 주고, 가장 먼 사람을 빨강으로 바꾼다.
- **판 시간 상한:** 미션 예상 시간에 공개 시간을 더했다. 퀴즈·초성·숫자 근사는 문제당 2초, O/X는 문장마다 2초다.
- **머리 위 카드 구조:** `shared/Picks.luau`(새)가 화면 데이터의 `picks`(UserId → { text, verdict })를 만든다. `client/Billboards`는 이름표 위에 그 카드를 그린다(`View.picks`). `init.client`가 현재 미션 화면의 `picks`를 넘겨준다.

  - 실제 창 캡처(PrintWindow)로 머리 위 "3" 카드를 확인했다(`.qa/captures_11/5_답공개_머리위.png`).

## 검토 반영 (Codex 1차, 2026-10-27)
Antigravity는 사용 한도(약 6일 뒤 초기화)라 받지 못했다. **교차검증 일부 미완료**이고, 한도가 풀리면 받는다.

- **[P2] 채팅 답:**
  - 퀴즈 질문이 열려 있는 동안 질문 대상이 채팅에 답만 쓰면 그 사람의 답으로 센다. 대상은 4지선다·초성·결승(`3`, `3번`), O/X(`O`/`X` 대소문자 무관, `1`/`2`), 숫자 근사(정수, 쉼표 허용)다.
  - 그 줄은 다른 사람에게 전달하지 않는다. 보낸 사람 화면에는 남고, 본인에게만 "채팅 답 '3' 접수! 다른 사람에겐 안 보여요"가 뜬다.
  - 답은 처음 낸 것 하나만 친다(버튼이든 채팅이든). 두 번째 채팅 답도 숨기고 "답은 처음 낸 것만 쳐요"를 띄운다.
  - 숫자 근사에서 범위 밖 숫자는 숨기기만 하고 세지 않는다.
  - 답이 아닌 줄("2번 아닌가"), 투표, 다른 미션의 채팅은 그대로 전달된다. 질문 시간이 끝난 뒤의 숫자도 그대로 간다.
  - **구조:** `MissionRunner.chatAnswer`가 판정·집계하고, `ChatGate`의 전달 콜백이 메시지마다 한 번 묻는다(`ChatGate.isAnswer`, MessageId별 기억). 두 모듈은 서로 require하지 않고 `RoundService`가 `ChatGate.start(onChat, WordService.hides, MissionRunner.chatAnswer)`로 잇는다. 금칙어 판정 전달(`received`)은 예전처럼 먼저 한다.
  - **고친 함정:** Lua 패턴 `"^(%d)번?$"`의 `?`는 `번`의 마지막 바이트에만 붙어서 숫자만 쓴 `3`이 안 잡혔다. `"^(%d)$"`와 `"^(%d)번$"` 두 패턴으로 나눴다.
- **[P2] 숫자 근사:** 모두의 숫자를 보여 준 2초 뒤에 남은 사람을 다시 센다. 그사이 나간 사람은 판정하지 않고, 최소 인원(2명) 아래면 아무도 날리지 않고 "인원이 부족해서 이번 미션은 패스!"로 끝낸다.
- **[P2] 벨 퀴즈 시간 상한:**
  - 진행자가 마지막 판정 때 나가면 4지선다로 바뀌는 경로를 넣었다.
  - 진행자 교체로 벨이 다시 돌아올 수 있어서, 문제마다 `벨 시도 전부 + 4지선다 한 문제(도입+답 시간+공개+정답)`로 잡는다. 모드별 값은 `BellQuiz.expectedFor`(바보 273초, 일반 258초, 똑똑이 249초)다.
  - 테스트 7j는 바보 모드 최악 경로를 실제로 돌려 235초가 상한 안에 드는지 잰다.
- **[P2] 작은 화면 카드:**
  - Studio 기기 시뮬레이터(갤럭시 A06, 705×338)에서 재 보니, 카드 위치는 상단 바(58px) 아래부터 세는데 60% 선은 화면 전체 기준이었다. 그래서 퀴즈 카드가 실제로는 화면의 77%까지 내려왔다. 상단 바를 빼고 계산하게 고쳤다.
  - 이 화면에서 60% 선을 지키려면 퀴즈 카드가 0.2배가 되어 단추를 누를 수 없다. 그래서 최소 크기를 0.5배(`CARD_MIN_SCALE`)로 두고, 작은 폰에서는 카드가 60% 선을 조금 넘는 것을 받아들였다(A06에서 퀴즈 카드 74%, 다음 게임 투표 카드 78%). 카드는 반투명이다.
  - 0.5배로도 큰 카드(10명 룰렛)는 화면 높이 90%·너비 90%(`SCREEN_ROOM`)를 넘지 않게 그보다 더 줄인다. 진행 중 대화 한 줄은 예전 규칙(높이 80%)이다.
  - PC(2205×909)에서는 1배 그대로이고, 투표 카드는 40%, 퀴즈 카드는 37%에서 끝난다.
  - 캡처: `.qa/captures_11/6_A06_고치기전_0.57배.jpg`, `7_A06_고친뒤_0.5배.jpg`.
- **[P3] O/X:** 문장이 열릴 때 날아가는 중이라 질문받지 않은 사람은, 공개 중에 돌아와도 맞음·틀림 카드가 붙지 않는다(질문 대상 ∩ 지금 남은 사람).

### 확인
- **테스트:**
  - 미션 7j(벨 퀴즈 최악 경로 실측), 7k(모드별 상한).
  - 미션 17q·17r(숫자 근사 재확인), 17s(O/X 카드).
  - 미션 17t~17w(채팅 답: 4지선다·O/X·숫자 근사, 첫 답만, 대상 아님, 시간 전후).
  - 라운드 15g·15h(실제 전달 콜백: 답은 보낸 사람만 보고 집계, 답이 아닌 줄은 전달, 질문 뒤에는 전달).

- **Studio(로컬 QA 장소, 혼자):**
  - 퀴즈를 띄우고 클라이언트에서 실제 채팅(`TextChannel:SendAsync("2번")`)을 보냈다. 서버가 답 2로 세어 머리 위 공개에 "2"가 떴고, 본인에게만 접수 안내가 왔다. 콘솔 오류는 없었다.
  - Studio의 채팅 필터 때문에 메시지가 서버에 닿기까지 몇 초 걸렸다. 질문 시간 막바지에 친 채팅 답은 늦어서 안 셀 수 있다. 버튼은 바로 간다.

## Codex 재확인 (1회, 커밋 1c4c690)
- **결과:** 지적 1·2·3·5는 해소로 봤다. 4(작은 화면)는 "부분 해소"로 봤다. 60% 보장은 풀렸지만 0.5배 하한과 화면 90% 상한은 조작성을 위한 합리적인 절충이라 받아들일 수 있고, 새 P2로 보지 않는다고 했다.
- **[P2] 새로 찾은 것과 수정:**
  - 문제: 채팅 `1`이 접수된 뒤 단추 `2`를 누르면 서버는 `1`로 채점하는데, 화면은 `2`를 고른 것으로 보였다.
  - 수정: 서버가 채팅 답을 세면 본인 안내(Notice)에 `answered = { id, choice }`를 같이 보낸다. 클라이언트(`MissionPanel.answered`, `init.client`에서 연결)는 그 질문의 내 선택을 서버 값으로 덮어쓰고 카드를 다시 그린다.
  - 내 선택이 정해지면 단추는 잠긴다. 안내가 오기 전에 누른 단추도 서버 값으로 바뀐다.
  - Studio(혼자): 채팅 `1`이 접수된 뒤 공개 단계에서 1번 단추가 '내 선택' 주황색(`Style.PICK`)으로 칠해졌다. 고치기 전에는 채팅 답이 화면의 내 선택에 반영되지 않았다. 혼자서는 답하자마자 질문이 닫혀 "채팅 뒤 단추" 순서를 직접 누르지는 못했다.
- **[P3] 반영:**
  - 17s는 복귀자를 처음부터 날아가는 중으로 둬서 예전 코드에서도 통과했다. 시작 때는 땅에 있다가 첫 문장 전에 날아가게 바꿨다. 예전 코드(`still`)로 잠깐 되돌려 17s가 실패하는 것을 확인했다.
  - 채팅 답 판정 기억은 500개마다 통째로 비우던 것을 두 세대로 바꿨다(직전 묶음을 한 번 더 기억). 같은 메시지가 전달 도중 다시 판정되지 않는다.
- 재확인은 규칙상 1회라, 새 P2 수정은 Codex에 다시 받지 않았다. Antigravity 한도가 풀리면 묶음 12 전체 검토 때 같이 본다.

## 폰 상태판 줄이기 (오너 2026-10-27)
- **요청:** "모바일의 경우 위쪽에 있는 모드 이름, 퀴즈, 미션, 내 목숨, 생존, 설정이 있는 UI가 되게 커 보이는데 모바일만 크기를 좀 줄일 수 있어?"
- **바꾼 것:**
  - 폰(터치 화면이고 키보드 없음, `Style.PHONE`)에서 상태판을 0.75배로 그린다(`Style.BOARD_SCALE`, 상태판의 `UIScale`). 상태판에 붙은 모드 표시와 "설정" 단추도 같이 줄어든다. 설정 단추는 56×44에서 42×33이 된다.
  - 상태판 아래 줄들(`Style.row`: 안내 줄, 미션 카드, 채팅 참가·진행 지원 단추, 구조 줄)은 줄어든 만큼(16px) 위로 올라간다. PC는 그대로다(행 0 = 80px).
  - 폰 판정은 Hud에 따로 있던 같은 식을 `Style.PHONE` 하나로 모았다.
- **확인:** Studio 기기 시뮬레이터(갤럭시 A06)에서 상태판이 352×64에서 264×48로 줄었다. 안내 줄은 80에서 64로, 미션 카드는 110에서 94로 올라갔다. 캡처: `.qa/captures_11/8_A06_상태판_0.75배.jpg`.
- **그대로 둔 것:** 상태판 아래 빨간 안내 줄(글자 16px)은 오너가 꼽은 목록에 없어서 크기를 그대로 뒀다. 그래서 폰에서는 이 줄이 상태판보다 넓어 보인다.
