### 8a 교차검증 (Codex 1번 + 새 Claude 검토자 1번 + Codex 재확인 1번)

두 검토자 모두 P1 없음.
- **둘 다 P2:** 연쇄 2번째부터 탈락하는 사람의 카메라가 쇼 → 기본 → 쇼로 튐(목숨 알림이 지연 발사보다 먼저 옴) → 목숨 알림 항목에 `launchIn`(차례까지 남은 초)을 싣고 클라이언트가 그만큼 쇼 카메라를 유지, 발사 신호에서는 카메라를 먼저 켜고 흔듦. 흰 번쩍임이 탈락 빨간 번쩍임과 같은 화면 틀·색을 써서 서로 덮음 → 흰 번쩍임 전용 틀, 숫자는 `Config.FLASH_WHITE_*`.
- **Codex만 P2:** 차례를 기다리는 동안 캐릭터만 바뀌면 옛 몸이 날아갈 수 있음 → `Character` 변경 감시 + 발사 직전에 같은 몸·생존·의자 주인 재확인. 최장 비행자가 나가면 비행 시상이 통째로 사라짐(Claude는 P3) → 사람별 최고 기록, 남은 사람 중 최댓값(동률 함께). 실패하고 바로 나간 사람의 분석 이벤트가 빠짐 → 게임 시작 때 `MissionPlayed`, 목숨을 잃는 순간 `MissionLifeLost`.
- **P3(고침):** 움직임 줄이기면 빨간 탈락 번쩍임도 끔(소리는 남김), 진행자가 고른 게임이 실제로 쓰였을 때만 `chosenBy = presenter`, 투표 수는 미션 id로, 흔들리는 중 카메라 모드가 바뀌면 매 프레임 자리를 다시 읽음, 주석·문서(크기 공식, 머리말들, 시작 조건의 연쇄 대기).
- **P3(남김):** `overPool`이 앞뒤 경계는 보지 않음(착지 기록이 드물게 수영장 밖에서 확정될 수 있음), 시험용 의자 가짜가 `delay`를 복귀 시점에 반영하지 않음·대기 중 취소 시험 없음(실제 SeatService는 Studio에서만 돎), 너무 적어 시작하지 못한 게임도 `MissionPlayed`가 한 번 나갈 수 있음, Studio 전용 `DevFling "out"`이 차례를 기다리는 사람에게 오면 바로 관람석.
- **재확인(Codex):** 다섯 P2 모두 고쳐짐, 새 P1 없음. 새 P2 하나 — 비행 기한을 늘린 뒤 다시 보는 예약이 옛 기한 그대로라 카메라·결과 창이 늦게 풀릴 수 있음 → 기한이 바뀔 때마다 그 시각에 다시 보도록(`flyingUntil`). 규칙상 재확인은 1번이라 이 수정은 다시 검토받지 않았다.
