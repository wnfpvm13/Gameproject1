# V3 채팅 참가 — 만든 기록 (2026-10-23, 1단계 묶음 2c)

후임 에이전트용 기록이다. 규칙은 `docs/DESIGN_V3.md` 7번(채팅 참가)·2번(대기실)·12번이 기준이고, 여기에는 어떻게 만들었고 무엇을 시험했는지 적는다. 판 규칙(묶음 2b)은 `docs/ROUND_RULES_2026-10-22.md`.

## 무엇이 들어갔나

- **채팅으로 참가(오너 2026-10-23):** 음성 채팅이 없는 계정 중 채팅이 되는 계정만 대기실에서 "⌨ 채팅으로 참가"를 고를 수 있다. 음성 계정은 연결 전이어도 음성으로 참가한다. 음성 준비(마이크 테스트 통과)가 된 사람도 고를 수 없다.
- **서버 확인:** 들어온 플레이어마다 한 번 음성 계정인지(`VoiceChatService:IsVoiceEnabledForUserIdAsync`)와 채팅 가능 여부(`TextChatService:CanUserChatAsync`)를 본다. 결과는 그 플레이어에게만 보낸다(리모트 `ChatAccess`: checking / yes / no / voice / error). 채팅 제한(보호자 설정 등)이 다른 사람에게 드러나지 않게 하려는 것이다.
    - 음성 확인이 실패하면 "음성 없음"으로 본다(오너 결정).
    - 채팅 권한 확인이 실패하면 5초, 20초 뒤에 다시 확인한다. 그래도 안 되면 라이브에서는 "error"(채팅 참가 불가)이고, Studio에서는 시험을 위해 허용한다. 실패할 때마다 경고를 남긴다.
- **판 동안 고정:** 판에 들어간 사람의 참가 방식은 그 판이 끝날 때까지 바뀌지 않는다(판 중 취소·음성 연결 무시). 결과 화면부터는 다시 바꿀 수 있고, 판 정리 때 음성이 준비된 채팅 참가자는 음성 참가로 바뀐다.
- **음성 차단:** 판 동안(배정부터 결과 전까지) 채팅 참가자의 음성은 누구에게도 들리지 않는다(판 중에 연결돼도).
- **말풍선 강조:** 채팅 참가자의 Roblox 말풍선은 노란 바탕, 굵은 글씨, 22 크기, 앞에 "⌨ "가 붙는다(번역문으로 보는 사람에게도). 채팅창에는 이름 앞에 진한 노랑 굵은 [채팅]이 붙는다. 글 내용은 바꾸지 않는다(받은 글 앞에 표시만).
- **말풍선 거리·높이:** 모든 말풍선이 150스터드까지 줄지 않고 200스터드까지 보인다(쇼 카메라 43~49, 관람석 먼 끝 약 120). 말풍선에 수직 간격 2.5스터드를 더해 머리 위 이름 + 하트 표시와 겹치지 않게 했다(기본 아바타로 확인).
- **아직 없는 것(묶음 5):** 채팅 판정, 전달 규칙(생존자가 아닌 사람의 글을 생존자에게 안 보냄), 귓속말 차단.

| 모듈 | 하는 일 |
|---|---|
| `server/services/ChatService` (새) | 음성 계정·채팅 권한 확인(재시도 포함), 그 플레이어에게만 `ChatAccess` 보내기, 채팅 참가 요청 검사(가능 = 채팅 되는 무음성 계정, 음성 준비 아님, 이번 판에 고정 아님), `Match.chatJoin`과 공개 속성 `BW_ChatMode`. Studio에서는 `workspace` 속성 `BW_ChatAccess`(yes/no/voice/error)로 결과를 강제할 수 있다(음성 계정으로 채팅 모드 시험) |
| `server/RoundService` | `ChatJoin` 리모트(참/거짓만, 플레이어당 `CHAT_JOIN_COOLDOWN` 1초), `Ready`가 켜지면 음성 참가로, `Sync` 때 `ChatAccess`도 다시 보냄, 배정 때 참가자의 `chat` 표시와 음성 차단, 결과·정리 때 음성 열기와 참가 방식 정리, 퇴장 때 방송 전에 채팅 선택 지우기 |
| `server/services/VoiceService` | `setSilenced(ids)`: 그 사람들의 `AudioDeviceInput`은 허용 목록을 비워 아무도 못 듣게. 판 중에 새로 생긴 입력에도 적용 |
| `server/Match` | `chatJoin`, 참가 가능 조건에 채팅 참가 포함, 참가자의 `chat` |
| `client/ChatLook` (새) | `TextChatService.OnIncomingMessage`([채팅]), `OnBubbleAdded`(노란 말풍선, 빈 글은 그대로), `BubbleChatConfiguration` 거리·높이(없으면 10초 기다리고 경고) |
| `client/UI/MicPanel` | 음성·마이크 안내 두 줄 + "채팅으로 참가 / 채팅 참가 취소" 버튼. 확인 중·실패·불가·음성 계정마다 안내가 다르다. 문구는 모두 `Config.TEXT` |
| `client/State`, `init.client` | `State.chatAccess`(서버가 나에게만 보낸 값), `BW_ChatMode` 변경 반영 |
| `default.project.json`, `tools/install_game.py` | 장소 채팅 방식 `TextChatService.ChatVersion = TextChatService`. 스크립트(플러그인 포함)로는 못 바꿔서(쓰기가 RobloxScript 권한) Rojo 프로젝트에 넣었고, 설치기는 아니면 경고만 한다 |

`Config`: `CHAT_BUBBLE_MINIMIZE_DISTANCE` 150, `CHAT_BUBBLE_MAX_DISTANCE` 200, `CHAT_BUBBLE_TEXT_SIZE` 22, `CHAT_BUBBLE_VERTICAL_OFFSET` 2.5(묶음 5에서 머리 위에 단어 줄이 생기면 줄당 1스터드 올린다), `CHAT_JOIN_COOLDOWN` 1, `CHAT_CHECK_RETRIES` {5, 20}. 새 문구(VOICE_*, MIC_*, READY*, HEADSET_TIP, OR_CHAT, NO_VOICE_NO_CHAT, CHAT_*)는 `Config.TEXT`에 있고 자동 문구 검사(`server` 시험 4)를 통과한다. 대기실 문구 NEED_READY는 "참가 준비된 플레이어 %d명 더 필요해요"로 바꿨다(채팅 참가자도 셈).

## 작성자가 정한 기본값 (오너가 바꿀 수 있음)

- 채팅 권한 확인이 계속 실패하면 라이브 서버에서는 채팅 참가를 막는다(관전). Studio에서만 허용한다.
- 마이크 안내의 "이어폰을 쓰면"을 "헤드셋을 쓰면"으로 바꿨다("이어폰"이 단어장 단어라 문구 검사에 걸림).
- [채팅] 색은 진한 노랑(#F2A900) 굵은 글씨다. 처음 넣은 밝은 노랑은 흰 홀 위 채팅창에서 흐려서 바꿨다.

## 시험한 방법

- **가상 시계 시험**(`round` 묶음):
    - 8번 채팅 참가 25개(재확인 뒤 4개 추가):
        - 확인 한 번과 본인에게만 알림.
        - 채팅 불가 계정과 음성 계정.
        - 채팅 권한 확인 실패: 재시도 뒤 라이브 불가, 재시도 성공, 경고.
        - 음성 확인 실패는 음성 없음.
        - 확인 중 요청 거절, 확인 중 퇴장.
        - 요청 간격, 참/거짓이 아닌 요청 무시.
        - 음성 준비 → 음성 참가, 취소.
        - 라이브의 참가 가능 조건, 퇴장 때 방송의 준비 인원.
        - 판: 채팅 참가자 음성 차단과 고정, 결과 때 음성 열기와 선택 변경, 판 뒤 음성 참가로 정리.
        - Sync 때 다시 보내기, 음성 확인 중 퇴장, Studio 최종 실패 시 허용, Studio 설정 `BW_ChatAccess`.
    - 9번(실제 VoiceService 모듈, 가짜 입력 장치) 5개: 생존자는 모두에게, 채팅 참가자는 아무에게도, 관전자는 관전자끼리, 판 중에 연결한 음성에도 차단 적용, 판 뒤 모두 열림.
    - 헛통과 확인: "음성 계정 거절"과 "본인에게만 알림"을 일부러 깨면 해당 시험(8k, 8a)이 실패하는 것을 확인하고 되돌렸다.
- **정적 검사:** 새 문제 0건. **의존 방향:** 33개 모듈, 64개 require, 층 규칙·순환 없음.
- **Studio v3_fling(옛 채팅 방식):**
    - 대기 중 버튼과 안내("음성 채팅 연결 필요…", "⌨ 채팅으로 참가")를 확인했다. 누르면 "채팅으로 참가해요 · 판 중에는 음성이 꺼져요" / "채팅 참가 취소"로 바뀐다.
    - 판 중에는 안내·버튼이 숨고, 판 중 취소는 서버가 거절한다. Studio 시험 계정에는 음성 입력 장치가 없어 음성 차단은 Studio에서 볼 수 없다.
- **Studio v3_chat(새 QA 장소, 오너 허락 2026-10-23):**
    - v3_pool 창(맵만 있던 저장 안 된 창)을 닫고, `rojo build default.project.json -o .qa/v3_chat.rbxlx`(채팅 방식 TextChatService)로 만든 장소에 맵·조명·게임 코드를 설치했다.
    - 채팅 참가로 의자에 앉은 뒤 클라이언트에서 `TextChannels.RBXGeneral:SendAsync`로 글을 보내고, Studio 창만 `PrintWindow`로 찍었다(MCP 캡처는 말풍선을 안 그림).
    - 확인: 쇼 카메라 거리에서 노란 "⌨ 안녕하세요 채팅 참가자 시험" 말풍선이 줄지 않고 보임, 채팅창 "[채팅] dogyes: …".
    - 고친 것: 채팅 말풍선이 머리 위 하트를 덮음 → 수직 간격 2.5. [채팅]이 흐림 → 진한 노랑 굵게. 다시 찍어 확인했다.
    - 검토 뒤: 오너 계정(Studio 시험 계정)은 음성 계정이라 서버가 "voice"로 판정했다. 채팅 버튼이 사라지고 채팅 참가 요청이 거절되는 것을 확인했다(공개 속성 `BW_CanChat`도 없음). 그다음 `BW_ChatAccess = "yes"`로 채팅 모드에 들어가 "음성 채팅을 쓸 수 없는 계정이에요 / 음성 대신 채팅으로 참가할 수 있어요" → 참가 → 노란 말풍선을 다시 찍어 확인했다.

## 교차검증 (Codex 1번 + Claude 검토자 1번)

- **Codex**(로컬 파일 읽기는 이번에도 도구 오류, 붙여 준 자료와 공식 문서로 판단): P1 1건, P2 2건, P3 4건.
    - P1: 서버가 "음성 없음/미연결"을 검사하지 않고 클라이언트의 Ready에만 기댄다.
    - P2: MicPanel이 Config를 require하고 버튼 연결·배치 숫자를 패널에 둔다.
    - P2: 시험이 권한 확인 대기 중의 경쟁 상태와 실제 VoiceService 설정을 검사하지 않는다.
    - P3: 참/거짓이 아닌 요청이 취소로 처리됨, 확인 중인데 "관전만" 안내, `OnBubbleAdded`의 adornee 타입(`Instance?`), 말풍선 높이 기록 표현.
- **Claude 검토자**(새 에이전트, 시험·정적 검사·캡처 직접 확인): P1 없음, P2 2건, P3 여러 건.
    - P2: `BW_CanChat` 속성이 모든 클라이언트에 복제돼 계정 제한이 드러남. P2: 권한 확인이 한 번 실패하면 세션 내내 참가 불가 + 틀린 안내.
    - P3(오너 확인 권장): 음성이 매번 연결 안 된 상태로 시작해서 거의 모든 음성 사용자가 채팅 버튼을 봄.
    - P3: 퇴장 방송의 준비 인원, 판 뒤 카운트다운 동안 남는 채팅 안내, NEED_READY 문구, BubbleChatConfiguration이 없을 때, 빈 글·번역문·adornee, 버튼 위치 숫자 중복, "음성을 연결하면…" 안내와 버튼이 엇갈림, 문서 어긋남(2b까지, 묶음 5의 음성 차단, RoundService 머리말, 높이 표현, 필터 전 글), 시험의 약한 곳.
- **판단과 반영:**
    - Codex P1과 Claude의 오너 확인 의견: 오너에게 물었다. 오너가 "음성 계정은 음성으로만"(추천안)을 골라서, 서버가 음성 계정을 확인하고 음성 계정은 채팅 참가를 못 하게 했다. 음성 확인 실패는 음성 없음으로 본다. 연결 여부 자체는 서버가 알 수 없으므로 이 결정으로 문제를 없앴다.
    - Codex P2(MicPanel 규칙): 동의하지 않았다. 층 규칙(`check_deps.py`)에서 UI 패널은 shared(Config 포함)를 쓸 수 있고, 패널이 자기 버튼을 init.client가 준 콜백에 잇는 것은 ReactionBar와 같은 방식이다. 배치 숫자는 원래 UI 모듈에 둔다(Config는 조정할 규칙 숫자). 다만 버튼 위치의 행 계산 중복은 `Style.row`로 없앴다.
    - Claude P2 2건: 고쳤다(본인에게만 `ChatAccess`, 실패 재시도와 "확인 중"·"확인 실패" 안내).
    - Codex P2(시험): 고쳤다(대기하는 가짜 확인으로 경쟁 상태, 실제 VoiceService 시험, 호출 횟수).
    - P3: 전부 고쳤다(참/거짓 검사, 상태별 안내, adornee 타입·빈 글·번역문, 설정 객체 대기, 퇴장 순서, 정리 시점, NEED_READY, `Style.row`, 문서). 남긴 것 없음.
- **Codex 재확인(1번):** 남은 P1/P2 없음. 지난 1~5번은 고쳐짐으로 봤고, 2번(MicPanel 규칙)은 작성자 판단에 동의해 철회했다. 남은 것은 P3 2건이었다.
    - P3: 음성도 채팅도 안 되는 계정에게 처음 15초(아직 "연결 안 됨"으로 보이는 동안) "음성을 연결하면…"을 안내함.
    - P3: 음성 확인 중 퇴장하면 채팅 권한 조회가 이어짐.
    - 빠진 시험 지적: Sync 때 다시 보내기, 음성 확인 중 퇴장, Studio 최종 실패 시 허용.
    - 고친 것: 서버가 무음성 계정으로 본 사람(yes/no/error)에게는 "음성 채팅을 쓸 수 없는 계정"과 맞는 안내를 띄움, 음성 확인 직후 퇴장 검사, 시험 3개 추가(8v·8w·8x).
    - 함께 넣은 것: Studio 전용 `workspace` 속성 `BW_ChatAccess`(yes/no/voice/error로 결과를 강제, 라이브는 무시, 시험 8y). 오너 계정이 음성 계정이라 Studio에서 채팅 모드를 시험하려고 넣었다.
    - 규칙대로 재확인은 더 받지 않았다. 재확인 뒤 고친 부분은 시험·정적 검사와 Studio v3_chat 시험(`BW_ChatAccess = yes`로 채팅 참가 → 말풍선 다시 찍음)으로 확인했다.
