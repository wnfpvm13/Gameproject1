## 게임 규칙

- **자유 대화**: 생존자 전원의 모든 발화를 판정한다(턴 없음). 침묵으로는 탈락하지 않는다.
- **판정**: NFC·소문자·숫자→한자어(7판→칠판)·문장부호→공백으로 정규화한 뒤 **연속 부분 문자열**이면 탈락.
  `사과` → "사과나무", "사과했어", "청사과" 탈락 / "의사 과학자", "사-과", "애플" 생존. 공백을 지워 붙이지 않는다.
- **누적 금칙어**: 시작 1개 → 경기 시간 30%에 2개 → 65%에 3개(3번째는 **사람마다 따로** 50% 확률로 말버릇: 진짜·대박…, V2.1.2).
  - 10초 전 예고("N초 뒤 금칙어가 N개로").
  - 최근 30초에 2명 이상 탈락했으면 최대 30초 미룬다.
  - 새 단어는 효력 시각부터 남에게 보인다.
  - 한 판에서 쓰이는 모든 단어는 서로 포함 관계가 없다(공원/놀이공원 동시 금지).
- **발화 경계(공정성, V2.1.2)**:
  - 클라이언트는 전사마다 "그 말을 시작했을 수 있는 시각의 범위"(서버 시계 earliest~latest)와 "늦어도 언제 끝났는지"(ended)를 보낸다. 어느 발화 구간의 결과인지 확실하지 않으면 범위를 넓힌다.
  - 새 단어는 범위 전체가 효력 뒤일 때만 적용한다(확실하지 않으면 탈락시키지 않음).
  - 범위가 대화 시작 전이나 판 결정 시각(cutoff) 뒤에 걸치면 그 전사는 무시한다.
  - 판이 결정된 뒤에는 cutoff 전에 시작해서 **cutoff 전에 끝난 말만** 판정한다(`END_TOLERANCE` = 0). 전사에는 단어별 시각이 없어서, 종료를 걸친 말에는 종료 뒤의 말이 섞였을 수 있다. cutoff는 대화 시작 때 대화 종료 시각으로 미리 정해 두고, 탈락으로 판이 일찍 결정되면 그 시각으로 앞당긴다.
  - 서버는 시각을 더 엄격한 쪽으로 당기지 않는다(시작은 앞으로, 끝은 뒤로만). 앞당겨진 시작·늦춰진 끝은 판정을 관대하게만 만든다.
  - 판이 결정되면 서버가 각 클라이언트에 알리고, 그런 말의 결과가 다 올 때까지(최대 5초) 판정을 열어 둔다. 1.2초가 넘으면 "마지막 말을 확인하고 있어요…"를 띄운다.
- **경기 시간**: 2~3명 330초, 4~6명 450초, 7~10명 570초.
  - 생존 1명이면 즉시 종료("최후의 1인", 다른 사람이 다 나갔으면 "기권승").
  - 시간이 끝나면 "공동 생존".
- **탈락 연출**: 부저 + 빨간 화면 → 의자에서 위·바깥으로 날아가 0.5초 뒤 "펑"(색종이·연기, 몸은 숨김 + 사망).
- **유령**:
  - 3초 뒤 반투명(0.6)으로 링 밖 스폰에 부활한다.
  - 투명 장벽(반지름 14)에 막혀 의자 링 안으로 못 들어간다. 장벽은 Outsiders 충돌 그룹만 막는다.
  - 이모지 리액션(👏😂😱😮❤️, 1.2초 쿨다운)을 쓸 수 있다.
  - 음성은 유령·관전자끼리만 들린다.
  - 판이 끝나면 정상 캐릭터로 다시 태어난다.
- **보조 진행자**:
  - 판마다 테마 1개(회식 자리 / 방과 후 교실 / 단체 여행 계획 / 동네 중고 장터)를 정하고, 각자에게 느슨한 역할을 준다(연기는 자유).
  - 시작할 때 이야깃거리 1장을 보여 준다.
  - 25초 조용하면 이야깃거리, 50초 조용하면 사건(40초 쿨다운, 탈락 직후 12초는 쉼)을 띄운다.
  - 진행 중인 금칙어가 들어간 카드·역할은 쓰지 않는다. 한 판에 같은 카드를 반복하지 않는다.
- **카메라**:
  - 생존자는 자기 의자 뒤 9, 위 11 스터드에서 원 중심 위 6 스터드를 본다.
  - 좌우 42°가 화면에 들어오도록 세로 FOV를 화면비에 맞춘다(16:9 약 51°).
  - 이 높이는 925×468 창에서 잰 값이다. 건너편 3단 말풍선 위쪽이 118px, 가까운 의자 턱이 405px로, 상단 상태판(64px) 아래에 들어온다.
  - 상단 HUD는 상태판 하나(테마·내 역할 포함)로 줄였다. 사건·예고 문구는 가운데 테이블 위(화면 62%·71%)에 띄운다.
  - 유령·관전자는 일반 카메라로 걸어 다닌다.
- **STT 사용량**: 인식기는 마이크 테스트 중과 생존 참가자의 대화 중에만 켠다. 한도는 경험 전체 분당 1+5×CCU다.
- **반향 대책**: 대기실에 "이어폰을 쓰면 억울한 탈락을 막을 수 있어요"를 띄운다. 연속 3번 인식 실패 시 "음성 인식이 불안정해요" 알림을 띄운다.
- **점수(캐주얼)**: 생존 +3, 탈락 직전 마지막으로 말한 다른 생존자에게 유도 +1, 결과에 "유도왕".
- **재경기**: 결과 직후 다음 판 카운트다운은 8초(처음 15초).

## 코드 구조 (오너 지시: 파트별, 단방향 의존)

```
src/shared/            Config(숫자·고정 문구), Judge(정규화·포함 판정·겹침·조사)
src/server/
  Main.server          시작점: Net.init → RoundService.start
  Net                  리모트 생성·송신 도우미 (유일한 리모트 생성 지점)
  Match                판 상태 데이터 + 작은 조회 함수 (규칙 없음)
  RoundService         판 흐름. 서비스들을 시작·연결하는 유일한 모듈
  content/             데이터만: WordBank(명사 91·말버릇 14), Themes(테마 4 · 미션 12 · 공통 주제)
  services/            서로 require 하지 않음 (shared·Match·Net·content만), 필요한 연결은 RoundService가 콜백으로
    WordService        첫 단어·누적 일정·보이는 단어 payload
    JudgeService       발화 접수·경계·판정 → hit 콜백, 판 종료 정리(settle)
    MissionService     테마·미션 카드·조용할 때 이야깃거리/사건 (구 HostService)
    VoteService        미션 투표·마감 집계·발표
    GhostService       Outsiders 충돌 그룹·유령 외형·리액션
    SeatService        링 의자 착석·발사·"펑"
    VoiceService       평탄 볼륨·유령/관전자 음성 분리
    Scores             리더보드·유도 점수
src/client/
  init.client          연결만: 서버 이벤트 → State 갱신 → refresh()가 모든 부품을 다시 그림
  State                클라이언트가 아는 판 상태
  Speech               마이크 → STT (켜기/끄기, 발화 시작 시각 범위, 판 종료 대기, 인식 불안정 감지)
  RingCamera, Billboards(말풍선 최대 3단어+이름), Fx(펑·리액션), FlatVoice
  UI/                  Style(공용), Hud(상단판), Toast, MicPanel, HostPanel(사건·예고), MissionPanel, VotePanel, ReactionBar
```

- 이 의존 규칙은 `tools/tests/check_deps.py`가 검사한다(아래 "개발 도구" 절의 표).
- Rojo는 폴더를 통째로 매핑한다(`default.project.json`).
- `tools/install_game.py`는 같은 규칙으로 폴더를 걸어서 설치기(`tools/install_game.luau`)를 만든다. 새 파일을 빠뜨릴 수 없다.
- 맵은 `tools/build_lounge_map.luau`(Edit에서 실행)로 만든다.

## 어떻게 만들었나 (후임용)

1. **판정기 교체**: 받침 문법 슬롯 판정을 버리고 포함 판정으로 바꿨다. 보고서 §9.4 예시로 단위 테스트를 했다(luau CLI, 15건 통과).
2. **서버 모듈 분리**:
   - 700줄짜리 RoundService(모드·질문 카드·게스트 섞임)를 Net/Match/서비스 7개/데이터 2개로 나눴다.
   - 서비스 간 호출은 콜백으로만 한다(JudgeService.start(hit, speech)).
3. **클라이언트 분리**: 화면 부품마다 모듈을 따로 두고, 모든 화면 갱신을 refresh() 한 곳에서 한다.
4. **로컬 Studio 3인 테스트**: `.qa/patch_fast.luau`로 타이머를 줄인 사본에서 했다(이 숫자는 커밋 금지).
   - 실행 동안 `_G`가 공유되지 않아, 클라이언트 로그는 LocalPlayer 밑 StringValue(QALog)에 쌓았다(`.qa/v2_logger.luau`).
   - 확인한 것:
     - 테마·역할 배정, 누적 1→2→3과 예고
     - 포함 탈락(딸기우유→딸기), 유령 부활(투명 0.6, Outsiders)
     - 결과 공개(최후의 1인·공동 생존)
     - 효력 전 시작 발화 무시 → 효력 후 탈락, 배정 중·대화 시작 전 발화 무시
     - 장벽 탐침(Outsiders는 15에서 멈추고 Default는 통과), 리액션 전송, 나간 사람 처리
5. **고친 것**: 한 판에 같은 카드 반복, 가운데 장식이 건너편을 가림.
6. **Codex 코드 검토(12건) 후 수정**:
   - **음성 구간 매칭**: 끝난 구간 대기열에서 오래된 것부터 매칭하고, 구간 id를 함께 보낸다. 늦게 온 전사가 다음 문장의 시작 시각을 빌려 쓰지 않는다.
   - **긴 전사**: UTF-8을 검증하고 600바이트까지 글자 경계에서 자른다(예전에는 200바이트에서 바이트 단위로 잘려 뒤쪽 금칙어가 사라졌다).
   - **종료 시각**: 종료가 정해진 순간 `cutoffAt`을 고정한다. 그 뒤에 시작된 발화는 판정하지 않는다.
   - **중복 처리**: 문자열이 같다고 버리던 규칙을 없애고, 같은 구간 id만 버린다. 스팸은 3초에 6건으로 막는다.
   - **단어 추가 연기**: 효력 직전까지 다시 검사하고, 예고 시각도 다시 보낸다. 나간 사람을 뺀 모든 탈락을 센다.
   - **카드 안전 검사**: `{name}` 치환 후 최종 문장을 검사한다. 새 단어가 생기면 화면의 카드를 다시 검사해 숨긴다. 새 단어는 역할과도 겹치지 않게 뽑는다.
   - **재접속 처리**: 다시 태어나는 중인 캐릭터는 참가 대상에서 뺀다. 다른 사람이 다시 태어나면 말풍선을 다시 그린다.
   - **장벽**: 높이를 30으로 올리고, 1초마다 링 안에 들어온 유령·관전자를 밖으로 옮긴다.
   - **연결 위치**: VoiceService 시작을 RoundService로 옮겼다(연결은 RoundService 한 곳에서만).
   - **재확인 테스트**: 3인 판에서 다시 확인했다. 유령은 14.8 스터드에서 멈췄고, 판 진행 중 리액션이 전달됐으며, 2단어 말풍선(이름·역할 포함)이 상태판 아래에 표시된다.

## V2.1 — 미션카드 + 투표 (2026-10-20)

오너가 받은 "V2.1 미션·대화 유도 시스템" 보고서(본문 파일 미수령, 요약 기준)를 Claude·Codex가 상의해 적용했다.
오너 결정: 투표는 대화 후 짧게, 첫 범위는 미션+투표만(역할 개인정보·소품은 다음).
누출 규칙은 Claude·Codex 공동 권장안(비밀 단어 맞춤 금지)을 기본값으로 적용했다.

- **미션카드**:
  - 테마마다 미션 3개를 순서대로 진행한다(작은 이야기 흐름). 카드는 상황+문제, 목표, 현재 조건으로 구성된다.
  - 진행: 카드 → 25초 뒤 notice(조건 변화) → 40초 뒤 투표 12초 → 결과별 후속 조건(동률·무투표는 undecided) → 120초 뒤 다음 미션(V2.1.2부터는 대화 시간 ÷ 미션 수 = 110/150/190초).
  - 미션 결과로는 아무도 죽지 않는다.
- **투표**:
  - 생존 참가자는 말했는지와 상관없이 투표할 수 있고, 표를 바꿀 수 있다.
  - 득표는 마감 뒤에만 공개한다. 투표 중에도 대화와 판정은 계속된다.
  - voteKey = 라운드:순번:미션id. 마감 시점에 살아 있는 사람의 표만 센다.
- **누출 차단(핵심)**:
  - 테마·역할·미션·투표·조용할 때 카드는 비밀 금칙어를 전혀 보지 않는다. 단어와 따로 쓰는 missionRng를 쓰고, 단어 추가 때 카드 재검사·숨김을 하지 않는다.
  - 대신 모든 문구를 **단어장 전체**와 미리 검사한다(`tools/check_content.luau`, Studio Edit에서 실행. 현재 247개 문구 OK).

## V2.1.2 — 판정 경계 수정 + 미션 간격 (2026-10-20)

오너가 붙여 넣은 GPT의 V2.1.1 평가를 Claude·Codex가 코드와 대조했다(`docs/REVIEW_2026-10-20_gpt_v211_eval.md`).
GPT가 놓친 판정 문제 3건을 고치고, 긴 판에서 미션이 모자라는 문제를 고쳤다.

**오너 결정**
- 판정 경계 3건: 실기기 테스트 전에 지금 고친다.
- STT 장애 처리(판정 보류·일시정지·무효): 지금은 만들지 않는다.
- 미션 3개가 끝난 뒤: 판 길이에 맞춰 간격을 늘린다.

**고친 것**
- **말버릇 정보 누출**(Claude 발견, Codex 동의): 3번째 단어 종류를 판마다 한 번 뽑아 전원에게 같은 종류를 줬다. 그래서 남의 3번째 단어가 말버릇이면 내 것도 말버릇이고, 단어는 서로 안 겹치므로 후보가 14 − (다른 생존자 수)로 줄었다. 이제 사람마다 따로 뽑는다(`WordService.runSchedule`).
- **늦은 전사가 다음 발화의 시작 시각을 빌림**(Codex 발견): 결과가 3초 넘게 늦고 그 사이 다시 말하면, 이전 말이 새 구간의 시작 시각으로 판정됐다(새 단어 직전의 말이 효력 뒤로 오판 → 억울한 탈락).
  - `Speech`는 이제 전사마다 시작 시각 범위와 늦어도 끝난 시각을 보낸다. 3초 안에 결과가 없던 구간은 5초 더 "만료 구간"으로 두고, 그 뒤에는 버리지 않고 하나(`lost`)로 합쳐 다음 결과 하나까지 후보로 남긴다(60초 뒤 버림).
  - 결과는 들어온 순서대로 오므로, 아직 답이 없는 구간 중 **가장 오래된 것부터**(lost → 만료 → 대기) 매칭한다. 결과가 그보다 앞선 구간의 것일 수는 없다(Codex 검토로 순서를 고침).
  - 대기·만료 구간이 없을 때만 열린 구간을 10초 컷으로 본다. 컷 뒤 나머지 조각은 독백이 시작된 시각을 그대로 하한으로 둔다(컷 결과가 늦게 와도 나머지가 늦게 시작한 것처럼 보이지 않게, Codex 지적).
  - 결과가 속할 수 있는 다른 구간(남은 대기·만료 구간, 8초 넘게 열려 컷됐을 수 있는 조각)까지 범위에 넣는다. 추측이 틀려도 판정이 관대해질 뿐이다.
  - 서버는 범위 전체가 단어 효력 뒤일 때만 탈락시키고, 대화 시작 전이나 cutoff 뒤에 걸치면 무시한다.
  - 서버의 12초 하한 보정(`CHUNK_MAX`)은 없앴다. 오래된 시작 시각을 현재 쪽으로 당기면 오히려 엄격해졌다(Codex 지적). 클라이언트는 어차피 전사를 안 보낼 수도 있으므로 보정은 막는 효과도 없었다. 숫자가 아니거나 NaN이면 무시한다.
- **판이 끝날 때 늦게 온 결과를 버림**(Codex 발견): 고정 1.2초 유예 대신 `JudgeService.settle(cutoff)`.
  - 판정 대상: cutoff 전에 시작해서 cutoff 전에 끝난 말(`END_TOLERANCE` = 0).
    - 처음 구현은 "cutoff 전에 시작한 말"을 5초까지 모두 판정해서, 종료 뒤에 한 말로도 탈락할 수 있었다. Claude가 발견해 1.5초로 좁혔다.
    - Codex 재확인에서 1.5초도 종료 뒤의 말(종료 0.7초 뒤 금칙어)로 탈락시킨다는 지적이 나와 0으로 정했다.
  - cutoff는 대화 시작 때 대화 종료 시각으로 미리 정한다. 서버가 0.2초마다 시간 종료를 확인하므로, 그 사이 종료 직후에 시작한 말이 판정되던 틈이 사라진다(Codex 지적).
  - 서버가 `Settle{key, cutoff}`를 보내면, 각 클라이언트는 그런 말의 결과가 오거나 만료될 때까지 기다린 뒤(`Speech.waitSettled(cutoff, cutoff + END_TOLERANCE, SETTLE_MAX)`) `Settled(key)`로 답한다.
  - 서버는 살아 있는 참가자가 모두 답하거나 5초(`SETTLE_MAX`)가 될 때까지 판정을 열어 둔다. 1.2초가 넘으면 "마지막 말을 확인하고 있어요…"(`Config.TEXT.SETTLING`)를 띄운다.
  - 그동안 단계는 Talk로 남아 있어 클라이언트 인식기가 꺼지지 않는다(Codex 지적 반영). 아무도 말하고 있지 않으면 0.1초 만에 결과로 넘어간다(예전에는 항상 1.2초).
- **미션 간격**: `Config.MISSION_LENGTH`(120초)를 없애고 대화 시간 ÷ 미션 수로 정한다(330/450/570초 → 110/150/190초). 7~10명 판에서 미션 없이 남던 약 191초, 2~3명 판의 마지막 후속 대화 30초 잘림이 사라졌다.

**남은 위험(알고 넘어감)**
- 종료 직전에 금칙어를 말하고 종료를 넘겨 말을 이어 가면 판정하지 않는다(미검출 쪽, "버저비터 생존"). 종료 뒤에 한 말로 탈락시키지 않기 위한 선택이다. Roblox가 단어별 시각을 주면 `END_TOLERANCE`를 올릴 수 있다.
- 판 종료 때는 만료 구간(3초 안에 결과가 없던 구간)을 기다리지 않는다. 끝에 웃음·잡음이 있을 때마다 결과가 5초씩 늦어지지 않게 하려는 선택이고, 3초 넘게 늦은 결과는 드물다(Codex도 타당하다고 봄).
- 결과가 1분 넘게 늦거나, Roblox가 결과를 순서대로 주지 않으면 범위가 맞지 않을 수 있다. 둘 다 사실상 없다고 보고 넘어간다.
- 빈 구간(웃음·잡음) 뒤에는 다음 결과가 그 빈 구간에 매칭되며 범위가 한 문장만큼 넓어질 수 있다. 그래서 새 단어가 생긴 직후 첫 문장에는 적용되지 않을 수 있다(관대한 쪽). 판 종료 때는 이 때문에 결과가 최대 3초 늦어질 수 있다.

## 개발 도구 — 의존 방향 검사 · 정적 검사 · 공용 스킬 (2026-10-20)

오너가 고른 추천 3가지를 적용했다(규칙: `~/.claude/CLAUDE.md` — 한국어, Codex·다른 리뷰어 교차검증, 모듈화).

**의존 방향 검사 (`tools/tests/check_deps.py`, `run_tests.py`에 포함)**
- src/의 `require(...)`를 모두 읽어(대상 = 호출 안의 마지막 `WaitForChild("이름")`) 모듈마다 층을 정하고, 층마다 require할 수 있는 층만 허용한다.

  | 층 | require 가능 |
  |---|---|
  | shared(Config, Judge), Net | shared |
  | Match | shared, Net |
  | content(WordBank, Themes) | shared |
  | services/* | shared, Net, Match, content — **서비스끼리는 금지** |
  | RoundService(연결 담당) | shared, Net, Match, content, services |
  | Main.server | shared, Net, Match, RoundService |
  | UI/Style | shared |
  | UI의 패널들 | shared, Style — **패널끼리 금지** |
  | 클라이언트 부품(State, Speech, Billboards, Fx, RingCamera, FlatVoice) | shared |
  | init.client(연결만) | shared, 클라이언트 부품, UI |

- 순환도 찾는다. 서버와 클라이언트는 서로 require할 수 없다(shared만 공유).
- 모듈 이름은 src/ 안에서 겹치면 안 된다(이름으로 대상을 찾으므로 검사기가 잡는다). 이름을 찾을 수 없는 require(변수 등)도 실패로 처리한다.
- 새 폴더는 `layer_of`에 넣기 전까지 "층 없음"으로 실패한다. 조용히 통과하지 않는다. `.lua` 파일도 읽는다.
- 주석과 문자열을 먼저 지우고 읽는다. 그래서 주석·문자열 안의 require는 세지 않는다. 반대로 `---[[` 토글 안의 코드, `require (x)`(공백), 문자열 `\z` 줄 이어짐 뒤의 코드, 백틱 문자열 `{…}` 안의 require는 센다. 괄호 없는 `require"X"`는 이름을 알 수 없어 실패로 처리한다.
- 검사기 자체가 틀리지 않도록 자체 시험 17가지를 먼저 돌린다. 위반 13가지는 각각 기대한 이유로 잡혀야 하고, 주석·문자열 3가지는 무시돼야 하며, 순환 1가지도 확인한다.
- 현재 31개 모듈·require 64개가 규칙을 지킨다. luau-lsp `require-graph`로 같은 소스의 그래프를 뽑아 비교했더니 64개 간선이 정확히 같았다(파서 검증).
