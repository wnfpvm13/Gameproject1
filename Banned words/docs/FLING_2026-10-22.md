# V3 플라잉 체어 발사 — 만든 기록 (2026-10-22, 1단계 묶음 2a)

후임 에이전트용 기록이다. 규칙은 `docs/DESIGN_V3.md` 10번이 기준이고, 여기에는 어떻게 만들었고 무엇을 시험했는지 적는다.

## 무엇이 들어갔나

판 규칙은 아직 V2 그대로다(자유 대화·누적 금칙어·받아쓰기 판정). 그 위에 V3 수영장의 발사 연출만 얹었다. 판 규칙(목숨·결승·준비)은 묶음 2b에서 바꾼다.

| 모듈 | 하는 일 |
|---|---|
| `server/services/SeatService` | 의자 줄 착석(가운데 의자부터), 발사(래그돌·초속도·물보라 신호), 5초 뒤 복귀 신호, 래그돌 풀기, 재착석 |
| `server/services/SpectatorService` | V2 `GhostService`를 대신한다. 관람석 이동, 무대에 올라온 관전자 돌려보내기, 판이 끝나면 대기실로, 리액션 |
| `server/RoundService` | `onFlightOver`에서 판 번호·단계를 보고 재착석 또는 관람석을 고른다. 결과 화면은 발사가 끝난 뒤 보여 준다. Studio 전용 `DevFling` |
| `client/ShowCamera` | V2 `RingCamera`를 대신한다. 정면 쇼 카메라, 화면 폭에 맞춘 FOV, 카메라 종류가 바뀌면 다시 잡기 |
| `client/Fx` | 의자 좌석 젖힘(스프링 → 유지 → 천천히 복구), "펑" 소리·연기·불꽃·색종이, 물보라와 첨벙 소리 |
| `client/GetUp` | 래그돌이 풀리면 내 캐릭터를 일으킨다(상태 변경은 소유 클라이언트만 가능) |
| `client/Billboards` | 흰 배경용: 단어 카드 테두리를 남색으로 굵게, 이름은 남색 알약 위 흰 글씨 |
| `client/FlatVoice` | 감쇠 곡선이 적용되게 `DistanceAttenuationMode = Custom`도 직접 정한다 |

리모트: `Fling`(누가, 몇 번 의자, 비행 시간, 착수점), `Splash`(착수 위치), `DevFling`(Studio 전용).

## 발사 순서(서버)

1. Seat를 끄고 `SeatWeld`를 지운다. `RequiresNeck`·`BreakJointsOnDeath`를 끄고 `PlatformStand`를 켠다.
2. 루트 관절만 남기고 `Motor6D`를 끄고 `BallSocketConstraint`로 잇는다. 몸 파트는 충돌 그룹 `BW_Flying`(의자 `BW_Chairs`·서로와 안 부딪침), 밀도 0.45(물에 뜨게).
3. `SetNetworkOwner(nil)`. 착수 구역 안 무작위 점을 고르고 `Fling` 신호를 보낸다.
4. **한 프레임 뒤**에 포물선 초속도를 모든 팔다리 어셈블리에 준다(최고점 = 앉은 높이 + 20, 천장 기준 아래).
5. 0.2초 뒤 몸 파트의 충돌을 켠다(앉아 있던 발이 카펫에 닿아 있어서).
6. 몸이 물에 닿으면 `Splash`. 발사 5초 뒤 복귀 신호 → RoundService가 `endFling` 뒤 재착석이나 관람석.

## 조절 값 (`Config`)

`FLING_RETURN_SECONDS` 5, `FLING_APEX_HEIGHT` 20, `FLING_BODY_TOP` 4, `FLING_SPIN` 7, `FLING_FLOAT_DENSITY` 0.45, `FLING_COLLIDE_DELAY` 0.2, `CHAIR_FLAP_DEGREES` 80, `CHAIR_SNAP_SECONDS` 0.12, `CHAIR_HOLD_SECONDS` 0.8, `CHAIR_RECOVER_SECONDS` 2.5, `SOUND_BANG`·`SOUND_SPLASH`(Roblox 라이선스 Pro Sound Effects).

## 시험한 방법

- QA 장소: `rojo build default.project.json -o .qa/v3_fling.rbxlx` → Studio로 열고 `tools/build_pool_hall.luau`·`tools/build_pool_lighting.luau` 실행 → 플레이(혼자, Studio는 최소 1명).
- 발사: 클라이언트에서 `Remotes.DevFling:FireServer()`(F 키와 같음), 탈락 경로는 `FireServer("out")`.
- 궤적: MCP `execute_luau`로 서버(위치 기록)·클라이언트(`Fling` 신호의 착수점과 실제 착수 비교)를 따로 돌렸다. 코드를 고칠 때는 플레이를 멈추고 장소의 스크립트 Source를 저장소 파일과 같게 바꾼 뒤 바이트 수로 맞는지 확인했다.

## 결과와 고친 것

- **물에 가라앉음 → 밀도 0.45:** 처음에는 몸이 수영장 바닥(깊이 11)까지 가라앉았다. 이제 6스터드쯤 잠겼다 떠올라 2초쯤부터 물 위에 떠 있다.
- **착수점이 약 8% 짧음 → 한 프레임 뒤에 던짐:** 서버 프레임 기록에서 발사 첫 프레임의 휴머노이드 상태가 아직 Running이었고, 수평 속도만 처음부터 약 5% 작았다(걷기 제어가 제동). V2도 한 프레임 기다렸다. 고친 뒤 목표 대 실제 착수점: (4.7, 70.2)→(4.7, 70.3), (16.0, 75.7)→(16.0, 75.6), (19.1, 61.6)→(19.2, 61.9).
- **쇼 카메라가 일반 카메라로 바뀜 → 다시 잡기:** 시험 중 카메라 종류가 Custom으로 돌아간 적이 있다. 나중에 콘솔에서 원인을 찾았다. Studio MCP의 `execute_luau`가 호출 중에 바뀐 카메라 종류를 호출 뒤 되돌린다("The execute_luau changed camera type. Resetting ..."). 즉 시험 도구가 만든 현상이다. 그래도 리스폰 등으로 종류가 바뀌는 경우를 막도록, 쇼 카메라가 켜져 있으면 종류가 바뀌는 즉시 되돌린다(꺼진 뒤에 실행되는 예약은 무시). 카메라 상태를 시험할 때는 이 도구의 되돌리기를 감안해야 한다.
- **최고점이 화면 위 HUD에 걸림 → 최고점 26에서 20으로:** 몸 꼭대기는 약 25(천장 기준 40 아래)다.
- 확인한 것: 발사 5초 뒤 자기 의자에 앉음(체력 100, 래그돌 흔적 없음), 탈락하면 5초 뒤 관람석에 서 있음, 결과 화면은 비행이 끝난 뒤, 다음 카운트다운에 대기실, 다음 배정에 다시 의자. 자리 번호는 플레이 화면에서는 쇼 카메라 거리에서도 보인다(편집 화면 캡처에서만 안 보였다).

## 교차검증 뒤 고친 것 (Codex + Claude 검토자)

- 비행 중 캐릭터가 죽거나 사라지면 비행을 바로 취소한다(`Died`, `AncestryChanged`). 복귀 신호에 날아간 캐릭터를 넘겨 RoundService가 지금 캐릭터와 비교한다. Studio 시험: 공중에서 체력 0 → 새 캐릭터는 대기실에 생긴 뒤 관람석으로 갔고, 5초 복귀 신호가 새 캐릭터를 옮기지 않았다.
- 발사 뒤 점프 잠금을 푼다(관람석 계단을 오를 수 있게). 재착석하면 다시 잠근다. 시험: 관람석에서 점프 높이 7.2.
- 회전 방향을 뒤집어 진짜 뒤로 넘어가게 했다(머리가 먼저 수영장 쪽). 시험: 머리-루트 z 차이가 +1.6까지 갔다가 한 바퀴.
- 자리가 없는 사람(우리가 앉히지 않은 사람)과 체력 0은 발사하지 않는다.
- 쇼 카메라: 예약된 다시 잡기가 실행될 때도 켜져 있는지 본다. `CurrentCamera`가 바뀌면 새 카메라에 다시 붙는다.
- 관전자: 판 중에 생긴 캐릭터(늦게 들어온 사람, 리스폰)도 관람석으로 보낸다. 무대 범위는 맵 계약(`ShowCamera`의 `HalfWidth`, 의자 위치, `CeilingY`)에서 계산한다. 자리는 단 가운데(x 50.0 / 53.6), 21명부터는 반 칸 옆.
- 일으키기: 소유권이 늦게 와도 되게 0.2초 간격으로 5번까지 다시 시도한다.
- 소리: 발사·물보라 소리는 복사본을 틀어 동시에 터져도 끊기지 않는다.
- 숫자는 Config로 옮겼다(`CHAIR_OVERSHOOT_DEGREES`, `CHAIR_SETTLE_SECONDS`, `GETUP_*`, `STAGE_BEHIND_ROW`, `STAND_SPOTS_PER_ROW`, `SYNC_COOLDOWN`).
- 예전부터 있던 것: `Ready`는 값이 바뀔 때만 상태를 보내고, `Sync`는 1초에 한 번만 받는다. 받아쓰기 `textId`는 유한한 정수만 기록한다(NaN 키 오류 방지). 쓰지 않게 된 `Match.loading`을 지웠다.
- Codex 재확인(1번, 첫 시도는 Codex 실행 환경 오류로 파일을 못 읽어 diff를 붙여 다시 받음): 10건 중 9건 고쳐짐. 남은 1건(판 시작과 캐릭터 로딩이 겹치면 관람석으로 못 감)은 "준비된 뒤에 판 진행을 확인"하도록 고쳤다(재확인은 규칙대로 더 받지 않음). 관전자 41명부터 자리가 겹치던 것도 4칸 엇갈림으로 넓혔다.
