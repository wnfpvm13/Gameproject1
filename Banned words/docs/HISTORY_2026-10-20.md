## 개요와 현재 상태

현재 버전은 **V2.1.1**(커밋 `bb4b71e`, 2026-10-20)이며, 로컬 Studio 3인 테스트까지 통과했고 실기기 음성 테스트와 게시는 아직이다.

## 1단계 — 기획·설계 (10-17)

첫 설계의 결론은 "가능하다, 단 받아쓰기는 클라이언트가 하고 판정은 서버가 한다"였다. 로블록스 `AudioSpeechToText`가 2026-02 정식 출시됐고 2026-05부터 한국어를 받아쓴다.

**설계 문서**: Claude Docs 문서로 작성하고(판정 흐름도·아키텍처 그림 포함), 저장소에 `docs/DESIGN.md`로 사본을 두었다.

**처음 설계의 핵심 (이후 상당 부분 바뀜)**

- 한 판: 대기 30초 → 배정 10초(버전1은 출제 45초 추가) → 대화 4분 → 결과 15초
- 모드 4개: 버전1 직접 출제, 버전2 단어장, 버전3 누적 금칙어(후보), 버전4 팀전(후보)
- 판정: 어절이 금칙어로 시작하고 나머지가 조사·어미면 확정 탈락, 공백을 지워야 걸리면 "아슬아슬" 경고만
- 침묵 방지: 질문 카드 10초 안에 두 어절 이상, 두 번 놓치면 탈락
- 조작 대비 "증인 교차 확인", 호출 한도 초과 시 "판정 일시 정지"
- 안전: 받아쓴 문장 전체는 남에게 보여주지 않고, 걸린 금칙어만 표시

**재검토 1차 (Claude)**: "목숨 -1" 같은 남은 문구, 버전3 개수 계산 오류, 한글 이스케이프 실수("삐!"가 "샐!"로), 문서 코드 서식 오류를 고쳤다.

**재검토 2차 (Codex, 14건 전부 반영)**

- 가장 큰 오류: 서버에서 받아쓴다는 전제. 로블록스 서버는 오디오 처리가 꺼져 있어 클라이언트 받아쓰기로 바꿨다
- 문장 전체 표시는 소통 제한 우회 위험 → 걸린 금칙어만 표시
- 의심 판정 투표는 이해관계·2\~3인 문제로 빼고 경고만
- 공백 제거와 어절 경계 충돌, 질문 카드 간격·단답 통과, 유도 점수 추임새 수확, 팀전 단어 누출, 동률·이탈 처리, 호출 한도 대책 등

**같은 날 추가 조사**: 나무위키에서 원작 예능(무한도전 "세븐"의 금칙어 게임, KBS "위험한 초대"의 플라잉 체어)을 조사하고 로블록스 적합성 분석을 내서 `docs/RESEARCH_original_shows.md`에 남겼다. 추천 순서는 질문 카드 → 발동 연출 → 유령 훼방꾼 → 토크쇼 → 말버릇 모드였다.

## 2단계 — 음성 인식(STT) 검증 (10-17)

한국어 받아쓰기는 동작한다: 기계 음성 60문장 중 54개(90%)를 판정 규칙대로 잡았고, 말이 끝난 뒤 평균 0.76초(최대 0.81초)가 걸렸다. 같은 날 친구들과 실제 목소리 테스트도 무사히 돌아갔다.

**자동 프로브 (`tools/stt_probe/`)**

- 로블록스 음성 합성은 한글을 거부(InvalidText)해서, Windows 한국어 음성(Microsoft Heami)으로 WAV를 만들었다
- Studio 설치 폴더에 넣어 `rbxasset://sounds/...`로 읽고, `AudioPlayer → Wire → AudioSpeechToText`로 넣어 채점
- 놓친 것: 기린→"길이", 시계→"시기", "\~는 어디 있어?" 문장 4개는 소리는 감지됐는데 글자가 빈 채로 옴
- 단어만 단독으로 말하면 언어 감지가 틀림: 코끼리→"小キリ", 봄비→"Humbi", 칠판→"7판"
- 영어 문장은 한국어로 번역돼 나옴, 같은 문장이 두 번 오기도 함

**라이브 테스트 화면 (`tools/stt_live_test/`)**: 문장 60 + 단어 20 = 80문항을 보여 주고 본인 마이크로 채점한다. 결과는 DataStore `SttLiveTest_v1`에 저장한다. 음성 연결 안내와 마이크 진단 줄을 넣었다.

**알아낸 사실 (이후 모든 작업의 전제)**

- 게시된 장소에서만 동작한다(로컬 파일은 빈 결과). 테스트 장소 placeId 84102094280848 / universe 10771466383
- 게임 설정에서 음성 채팅 활성화 + `VoiceChatService.UseAudioApi = Enabled` 필수. "자동"이면 오류 없이 빈 결과만 나와 가장 오래 막혔다
- 2026-01부터 음성은 꺼진 채 시작한다. 플레이어가 ≡ 메뉴 → 설정에서 직접 연결해야 하고, 스크립트로는 켤 수 없다
- Studio의 "저장"은 게시가 아니다. 친구의 Roblox Player에서 테스트 창이 안 뜨던 원인이 미게시였고, "Roblox에 게시" 후 해결됐다
- 친구 초대는 Creator Hub의 오디언스 관리 → 얼리 테스터 초대로 했다
- 서버 최대 인원(`Players.MaxPlayers`)은 스크립트로 못 바꿔 경험 설정에서 10으로 바꿔야 한다(오너 처리)

## 3단계 — 프로토타입 v0, 수영장 (10-17\~18)

친구 테스트로 받아쓰기를 확인한 뒤, 수영장 의자에 앉아 대화하다 금칙어를 말하면 물로 날아가 죽는 처음 버전을 만들었다. 이후 오너 요청과 분석으로 기능을 더했다.

**만든 것**

- **맵**: 데크 120×90, 수영장 44×28(지형 물), 파라솔, 투명 울타리. 처음엔 타원형 의자였으나 "거리가 멀다"는 오너 지적으로 **의자 10개 일렬(5스터드 간격) + 수영장 위 고정 정면 카메라**로 바꿈
- **라운드**: 대기 → 카운트다운 15초 → 배정 6초 → 대화 240초 → 결과 8초, 최소 2명(Studio 1명)
- **의자**: 배정된 사람만 앉음, 일어나면 다시 앉힘, 점프·리셋 막음
- **탈락**: 의자 고정 해제 → 수영장 중앙으로 포물선 발사(최고 35스터드, 1.2초) → 사망 → 관전
- **말풍선**: 남의 단어, 내 건 `???`, 결과에서 전부 공개. 말풍선 안에 이름
- **단어장**: 버전2 단어 57개(카테고리 6개)
- **거리 무관 같은 볼륨**: 기본 음성 감쇠(7\~80스터드)를 서버·클라이언트 양쪽에서 평평하게(120스터드에서도 들림 1)
- **질문 카드**: 가장 오래 말 안 한 사람에게 질문, 10초 안 두 어절 이상, 첫 실패 경고·두 번째 탈락
- **탈락 연출**: 부저(Pro Sound Effects) + 빨간 화면, 말풍선이 빨겛게 커짐, 착수 지점 물보라 + 물 소리
- **유령 훼방꾼 + 점수**: 탈락자도 말해서 유도 가능, 탈락 직전 마지막 발화자 유도 +1, 생존 +3, "유도왕"
- **토크쇼(게스트) 모드 + 모드 투표**: KBS 위험한 초대 방식. 수영장 뗅목의 게스트가 패널 단어를 말하면 그 패널이 날아감, 패널이 남의 단어를 직접 말하면 반칙
- **10명 대응**: 화면비에 맞춘 FOV 계산, 참가 상한 10명, 넘치는 사람은 구경
- **텍스트 채팅 모드 없음**(오너 결정)

**테스트**: 1인(착석→???→탈락), 2인(서로 상대 단어만 보임), 3인 토크쇼(게스트 한 문장에 두 명 동시 발사, 게스트 교대, 반칙 탈락), 실계정 1명 + 인형 9개로 10석 말풍선 겹침 없음 확인, 넘침 처리(MAX 2에 3명 → 3번째 구경).

**고친 버그**

- 발사가 약함(18스터드) → 의자 고정(SeatWeld)을 먼저 지우고 한 프레임 뒤 속도
- 내 `???`가 안 뜨던 문제 → 상태를 먼저 보내고 단어는 나중에
- 조사 오류("을/를") → 받침에 맞추는 `Judge.josa`
- 기본 이름표가 말풍선에 겹침 → 라운드 중 이름표 숨기고 말풍선 안에 이름
- 클래식에서 게스트 뗅목이 화면 하단을 가림 → 토크쇼때만 표시
- 클라우드 장소에서 멀티 테스트가 저장된 옛 코드로 돌아감 → 로컬 Rojo 빌드 파일로 테스트

## 4단계 — 게임 방식 재검토 반영 (10-18)

Codex와 게임 방식을 검토한 결론은 "친구끼리는 재밌지만 공개 출시는 이르다"였다. 판정 신뢰도, 진입 마찰, 탈락 후 대기가 약점으로 꼽혔다(`docs/REVIEW_2026-10-18.md`).

**Codex가 짚은 주요 문제**

- 음성 준비가 안 된 사람도 의자에 앉아 참가함
- "치킨입니다·치킨으로도·컴퓨터라고"가 확정이 아니라 아슬아슬만(어미 부족)
- 토크쇼에서 유령이 패널 단어를 읽어 주면 게스트가 따라 말해 날릴 수 있음, 3인 토크쇼는 첫 탈락에 끝남
- 질문 카드 간격 계산 때문에 10명이면 모두 두 번을 못 채움
- 종료 직전 판정 유예가 없고 마지막 발사 연출이 잘림, 중간 입장 상태 동기화 불안
- 탈락 후 다음 판까지 최대 약 259초 대기

**오너 결정**: "유령은 삭제, 죽으면 관전만. 대화 시간은 3분으로 단축, 이후 재검토."

**반영한 것**

- 유령 삭제: 탈락자·관전자 목소리는 관전자끼리만 들림(`AudioDeviceInput` 접근 목록), 탈락자 문장은 판정 안 함
- 대화 180초, 종료 유예 1.2초 + 마지막 착수 대기
- 음성 준비 게이트: 음성 연결 + 마이크 테스트(아무 말 1번) 후에만 착석
- 판정 어미 보강(단위 검사 14건 통과)
- 질문 카드 발급 시각 기준 간격, 같은 답 재사용 금지, 인식 실패 면제(마이크에 말소리는 잡혔는데 글자가 안 온 경우)
- 토크쇼: 최소 4명, 단어장 나열 무효, 한 문장 최대 2명, 게스트 사망·이탈·침묵 45초면 판 종료
- 중간 입장 Sync 요청, 착수 범위 제한

**재검토(Codex 2차) 후 추가 수정**

- 조사 판정을 받침에 맞는 슬롯 문법으로 재작성했다. 긴 입력에서 계산이 폭증하는 문제와, 학원가→학원·고양이과→고양이 오탐을 고쳤다
- 리스폰 뒤 받아쓰기가 끊기는 문제를 고쳤다. 판정 종료 시각을 분리하고, 라운드 오류가 나도 복구되게 했다(xpcall)
- 이 수정분은 판정 테스트까지만 마쳤다. 4인 테스트 중 오너가 멈추라고 한 뒤 V2 전환으로 대체됐다

## 5단계 — V2 전환, 외부 보고서 (10-20)

오너가 다른 곳에서 받은 "V2.0 재검토 보고서"를 Claude와 Codex가 검토했고, 오너가 그 버전으로 바꾸기로 해 게임을 새로 짰다(커밋 `965148f`).

**보고서 검토 (Claude + Codex)**: 보고서는 우리 코드가 아니라 다른 "V1.0 턴제 설계서"를 기준으로 쓰여 있었다. 그래서 우리 게임에 해당하는 문제만 골랐다.

- 스피커 반향 오탈락(남이 내 단어를 말한 소리가 내 마이크로)
- STT 요청 한도 "분당 1 + 5×동접자"(공식 문서로 확인)
- 인식 장애 시 판정을 멈추는 장치 없음
- 버전1 미구현
- 질문 카드 침묵 탈락의 불공정

기록은 `docs/REVIEW_2026-10-20_external_report.md`에 있다.

**오너 결정**: "해당 버전으로 바꾸는 게 맞다." 맵은 원형 라운지, 서버당 1경기, 단어장+누적 먼저, 토크쇼 삭제. 작업 중에 "코드는 파트를 나눠 꼬이지 않게"도 더했다.

**바뀐 규칙**

| 맵 | 수영장, 의자 일렬, 고정 정면 카메라 | 원형 라운지, 의자 10개 링, 내 의자 뒤에서 원 안을 보는 카메라 |

**추가로 넣은 것**

- 보조 진행자(테마 4종·역할·주제 카드·사건)
- STT는 마이크 테스트 중과 살아 있는 참가자의 대화 중에만 켬(한도 절약)
- 대기실 "이어폰 권장" 안내, 인식 불안정 알림
- 단어장을 명사 91개 + 말버릇 14개(진짜·대박 등)로 늘렸다. 한 판에서 쓰는 단어끼리 서로 포함되지 않게 했다(공원/놀이공원 동시 금지)

**Codex 코드 검토 12건 + 재확인 6건 수정** (`docs/REVIEW_2026-10-20_v2_code_codex.md`)

- 늦게 온 받아쓰기가 다음 문장의 시작 시각을 빌려 쓰던 문제 → 발화 구간 대기열 + 구간 id
- 200바이트 절단으로 뒷부분 금칙어가 사라지던 문제 → UTF-8 검증 + 600바이트까지 글자 경계에서 자름
- 판 종료 후 시작한 말로 결과가 바뀜 → 종료가 정해지는 순간 `cutoffAt` 고정
- 같은 문장 반복을 무조건 버림 → 같은 구간 id만 제거, 3초 6건 스팸 제한
- 예고 뒤 연속 탈락에도 단어 추가가 안 밀림 → 효력 직전까지 재검사
- 유령 리로드 중 다음 판 참가 경합, 장벽을 가구 위에서 뛰어넘기 → 로딩 플래그, 장벽 30, 1초 가드
- 다른 사람 부활 뒤 말풍선 미복구, 발사된 몸이 가드에 끌려감 등

**화면 조정**: 건너편 말풍선이 상단 UI에 가려 카메라를 뒤 9·위 11·시선 높이 6으로 옮기고, 상단 HUD를 64px로 줄였다.

## 6단계 — V2.1 미션 카드 + 투표, V2.1.1 (10-20)

V2.1은 "말할 이유·소재·입장 차이·다음 사건"을 주는 미션 카드와 짧은 투표를 넣었고, V2.1.1은 보고서 본문을 반영해 카드를 접히게 하고 직함을 없잤다(커밋 `5e74db5`, `bb4b71e`).

**V2.1 (요약본 기준)**

- 오너 결정: 투표는 대화 후 짧게, 첫 범위는 미션+투표만. "앞으로 계속 GPT와 얘기 나누면서 해"
- 테마 4개 × 미션 3개 = 12개. 미션 = 상황·문제·목표·선택지 2\~3개
- 진행: 카드 → 25초 상황 변화 → 40초에 12초 투표 → 결과별 후속 조건 → 120초에 다음 미션. 미션 결과로는 아무도 안 죽음
- 투표: 살아 있는 참가자만, 표 변경 가능, 득표는 마감 뒤 공개, 동률·무투표는 "결정 못 함" 후속
- **누출 차단**: 카드·테마·투표는 비밀 금칙어를 전혀 보지 않는다(단어와 따로 쓰는 난수, 판마다 새로). 대신 모든 문구를 단어장 전체와 미리 검사한다(`tools/check_content.luau`)
- V2 때의 "진행 중 단어가 든 카드 건너뛰기"는 "이 카드가 나왔으니 내 단어는 여기 없다"는 추측 통로라 없앰다(Codex 지적)
- 화면: 양옆 이웃 말풍선이 화면 가장자리에 오므로, 미션 카드·투표·리액션을 아래 가운데에 모았다. 작은 화면은 압축 모드
- Codex 카드 검토로 약한 카드 3개(메뉴·반장·장터 부스) 교체. Codex 코드 검토 2회로 8건 수정(마감 순간 집계, 라운드 중단 시 투표 취소, 늦은 입장 동기화 등)

**V2.1.1 (보고서 본문 반영)**

- 오너 결정: 개인 역할·소품·버전1은 빼고, 실기기 테스트는 나중에. 고정 시간 유지, 접히는 카드, 직함 제거
- **접히는 카드**: 새 미션은 8초간 크게 보인 뒤 "제목 · 목표 · 현재 조건 · ✅ 결정"만 남기고, 누르면 펼친다. 미션 12개에 제목을 붙였다
- **자유 발언 안내**: "선택하지 않아도 자유롭게 이야기할 수 있어요", 투표 문구는 "투표는 자유예요 · 계속 이야기해도 돼요"
- **중요 연출은 한 번에 하나**: 금칙어 예고·추가, 탈락, 새 카드, 사건 배너가 떠 있으면 다음 단계·투표를 미룬다. 투표 결과는 마감 순간 집계, 화면이 비면 공개(그 사이 "결과를 곧 알려 드려요")
- **직함 제거**: 말풍선·상태판 역할 삭제, 지목형 사건 11개를 공통 문장으로
- **보고서 카드 3종 이식**: 영수증 대소동, 숙소 예약 사고, 중고 로봇 흥정. 원안 12종 중 8종은 우리 금칙어(계산서·여행·사진·고양이 등)가 문구에 들어 있어 그대로는 못 썼다
- **보고서와 다르게 유지**: 살아 있는 사람의 금칙어로 카드를 다시 고르는 방식(§10.2-3)은 추측 통로라 쓰지 않았다
- 검사 도구가 새 제목 2개의 금칙어 "회의"를 잡아냈다. 미션 카드가 화면 전체로 커지던 버그도 고쳤다
- Codex 계산: 330초 판에서 미션 3개가 결과까지 진행되고, 마지막 미션의 후속 대화 30초는 판 종료로 잘린다

## 현재 게임 규칙 (V2.1.1)

지금 게임은 "자유 대화 + 포함 문자열 판정 + 금칙어 누적 + 미션 카드·투표 + 유령 관전"이다. 숫자는 모두 `src/shared/Config.luau`에 있다.

**한 판의 흐름**

1. 대기: 음성 연결 + 마이크 테스트(아무 말 1번)를 한 사람만 준비 완료. 2명 이상(Studio 1명)이면 시작
2. 카운트다운 15초(결과 직후 재경기는 8초)
3. 배정 8초: 원형 의자에 고르게 착석(2명이면 마주보기), 금칙어 1개, 테마 1개
4. 대화: 2\~3명 330초, 4\~6명 450초, 7\~10명 570초
5. 결과 10초: 모든 금칙어 공개, "최후의 1인" / "기권승"(다른 사람이 모두 나감) / "공동 생존", "유도왕"

**판정**

- NFC·소문자·숫자→한자어(7판→칠판)·문장부호→공백으로 바꾼 뒤, 금칙어가 문장 어디든 연속으로 들어 있으면 탈락
- 사과 → "사과나무", "사과했어", "청사과" 탈락 / "의사 과학자", "사-과", "애플" 생존
- 새 단어는 효력 후에 시작된 말에만 적용. 대화 시작 전에 시작된 말과 판이 정해진 뒤 시작된 말은 무시
- 침묵으로는 탈락하지 않음. 미션 결과로도 탈락하지 않음

**금칙어 누적**: 대화 시간의 30%에 2개, 65%에 3개(3번째는 50% 확률로 말버릇: 진짜·대박·솔직히 등). 10초 전 예고, 최근 30초에 2명 이상 탈락하면 최대 30초 연기. 한 판의 단어끼리는 서로 포함되지 않음.

**미션 카드와 투표**

- 테마: 회식 자리 / 방과 후 우리 반 / 단체 나들이 계획 / 동네 중고 장터, 각 미션 3개 순서대로(판마다 같은 테마 연속 X)
- 카드 → 25초 상황 변화 → 40초에 12초 투표 → 결과별 후속 → 120초에 다음 미션
- 새 카드 8초만 크게, 이후 접힘(누르면 펼침). 투표는 살아 있는 참가자만, 선택 자유
- 중요 연출은 한 번에 하나(금칙어 예고·탈락이 먼저, 미션 단계·투표·사건은 기다림)
- 조용하면 30초에 이야깃거리 줄, 60초에 사건 배너
- 카드·테마·투표는 비밀 금칙어와 무관(누출 차단)

**탈락과 유령**

- 부저 + 빨간 화면, 말풍선이 빨겛게 커짐 → 의자에서 위·바깥으로 발사 → 0.5초에 "펑"(색종이·연기)
- 3초 뒤 반투명 유령으로 링 밖 스폰에 부활, 투명 장벽(반지름 14)으로 의자 링 안 출입 금지
- 유령·관전자: 이모지 리액션(👏😂😱😮❤️), 목소리는 유령·관전자끼리만

**음성·화면**

- 모두 거리 무관 같은 볼륨. 살아 있는 참가자는 내 의자 뒤에서 원 안을 보는 고정 카메라
- 남의 머리 위 말풍선(금칙어 최대 3개 + 이름, 새 단어는 노랑게 번쩍), 내 금칙어는 상태판에 "??? × n"만
- 대기실 "이어폰을 쓰면 억울한 탈락을 막을 수 있어요", 연속 3번 인식 실패 시 알림
- 점수(세션만): 생존 +3, 탈락 직전 마지막으로 말한 다른 생존자 유도 +1

## 코드 구조와 도구

오너 지시("파트를 나눠 꼬이지 않게")에 따라, 서비스끼리는 서로 부르지 않고 판 흐름 모듈(RoundService)만 이들을 잇는다.

```text
서버 (src/server)
  Main.server ──▶ RoundService (판 흐름: 대기 → 배정 → 대화 → 결과 → 재경기)
                   │  서비스끼리는 서로 부르지 않고, RoundService만 이들을 잇는다
                   ├─▶ services/WordService     금칙어 배정 · 1→2→3개 누적
                   ├─▶ services/JudgeService    말풍선 판정 (shared/Judge 사용)
                   ├─▶ services/MissionService  테마 · 미션 카드 · 조용할 때 이야깃거리/사건
                   ├─▶ services/VoteService     짧은 투표 · 마감 집계 · 발표 대기(pending)
                   ├─▶ services/SeatService     원형 라운지 의자 배정 · 착석
                   ├─▶ services/GhostService    탈락자 반투명 · 링 밖 관전
                   ├─▶ services/VoiceService    음성 경로: 거리 무관 같은 음량 · 유령끼리만 들리게
                   └─▶ services/Scores          세션 점수 · 유도 점수 (저장 안 함)
  공용 부품: Match (판 상태) · Net (원격 이벤트) · content/{WordBank, Themes} (데이터, 아무것도 부르지 않음)

공유 (src/shared)
  Config (모든 숫자 · 안내 문구) · Judge (포함 문자열 판정 규칙)

클라이언트 (src/client)
  init.client ──▶ State (서버 이벤트 저장) ──▶ refresh() 한 곳에서 모두 다시 그림
    부품: Speech (STT) · FlatVoice (거리 무관 같은 음량) · RingCamera · Billboards · Fx
    UI/: Style · Hud · HostPanel · MissionPanel · VotePanel · MicPanel · ReactionBar · Toast
```

데이터(content)는 아무것도 부르지 않고, 서비스는 Match·Net·content만 읽는다. 클라이언트는 서버 이벤트를 State에 담고 refresh() 한 곳에서 모든 부품을 다시 그린다. Rojo는 `src/` 폴더를 통째로 매핑하고, 설치 스크립트도 같은 규칙으로 폴더를 따라 만들어 새 파일이 빠지지 않는다.

## 남은 과제와 미검증 항목

가장 큰 미확인은 V2 이후 게임을 실제 목소리로 돌려 본 적이 없다는 점이다. 오너는 실기기 테스트를 나중에 하기로 했다.

**실기기에서만 확인 가능 (나중에)**

- 스피커 반향 오탈락: 남이 내 단어를 말한 소리가 내 마이크로 들어가는지(이어폰/스피커 × PC/폰)
- 실제 한국어 인식률과 포함 판정의 오탐, 동시 발화, 지연
- STT 요청량(분당 1 + 5×동접자 한도 대비)
- 휴대폰에서 말풍선·미션 카드 가독성
- 10명 동시 플레이(지금까지 로컬 4명까지)
- 투표 있음/없음 비교, 미션 카드가 조용한 사람을 돕는지

**기술 과제**

- 음성 통신 호환성 검사(`GetChatGroupsAsync`, 팀 테스트 필요)
- STT 장애 시 판정 보류(지금은 알림과 서버 경고 로그만)
- 클라이언트가 보내는 받아쓰기를 검증할 방법 없음(친선 게임 수준으로 운영)
- 마지막 미션의 후속 대화가 330초 판에서 약 30초 잘림

**게시·설정**

- 게시된 테스트 장소에 V2.1.1 설치 + 맵 빌드 + "Roblox에 게시"(아직 안 함)
- 서버 최대 인원 10 설정 확인(스크립트로 불가)

**보류한 기능 (오너: 굳이 필요할까)**

- 버전1(채팅으로 금칙어 직접 출제)
- 역할별 개인 정보, 역할 선택, 소품 상호작용
- 여러 경기장(서버 50명), 팀전, 말버릇 모드, 토크쇼(삭제됨)
