후임 에이전트용 기록이다. 규칙은 `docs/DESIGN_V3.md` 8번(진행자 운영)·12번이 기준이고, 여기에는 어떻게 만들었고 무엇을 시험했는지 적는다. 바로 앞 묶음은 `docs/CHAT_JOIN_2026-10-23.md`(2c 채팅 참가). 2c 상태는 git 태그 `banned-words-v3-2c`(2865d71)로 남겨 두었다.

## 오너 결정 (2026-10-23, 작성자 질문에 모두 추천안 선택)

- 범위: 진행자 틀 + 미션 메뉴 + 효과음 버튼. 주관 판정·레버·단상 꾸미기는 묶음 4.
- 보상: 끝까지 진행한 판마다 +2점(결과 화면에 "진행 이름"). 발사로는 점수 없음.
- 효과음: 버튼 5개, 같은 버튼 3초 간격, Roblox 라이선스 음원만.
- 음성 그룹 확인: 설계대로(실서버에서 확인이 실패하면 진행자 없음). 오너가 경험 설정 → Communication → "Chat & Voice Groups APIs"를 켠다.
- 여러 명 Studio 시험: 그 자리에서 해도 됨(새 창은 바로 최소화, 끝나면 닫기).

## 무엇이 들어갔나

- **지원:** 판에서 뛰고 있지 않은 사람(대기실, 관전 중, 목숨을 다 잃은 탈락자)에게 "🎤 진행자 지원" 버튼이 보인다(상태판 아래 3번째 줄). 누르면 "진행자 지원 취소"로 바뀌고 안내가 뜬다. 진행 중에는 같은 버튼이 "진행 넘기기"(지원 취소 = 물러나기)다. 채팅 참가자에게는 숨긴다(진행할 수 없음). 지원 여부는 공개 속성 `BW_Volunteer`.
- **선정(배정 때, 의자에 앉히기 전):** 후보는 지원자 중 음성이 준비됐고(라이브, `REQUIRE_VOICE_READY`) 채팅 참가가 아닌 사람이다. 이 세션에서 진행을 적게 한 사람부터, 같으면 무작위. 진행자를 빼고도 `MIN_PLAYERS`명이 남아야 한다. 진행자를 먼저 뽑고 그다음 의자 수(`MAX_PLAYERS`)로 자른다(지원자가 잘려 나가지 않게). 조건 확인은 기다리는(yield) 호출이라, 끝난 뒤 그 사람이 아직 지원 중·음성 준비·채팅 참가 아님·접속 중인지 다시 본다. 조건:
    - 음성 참가자 전원과 같은 음성 그룹이 하나라도 있다(`VoiceChatService:GetChatGroupsAsync`). 공식 문서는 결과를 "정렬된 배열의 배열"이라고만 하고 넘긴 플레이어 순서와 같은지 말하지 않아서, 한 번에 한 명씩 묻는다(최대 1 + 음성 참가자 수 번).
    - 채팅 참가자 전원 → 진행자로 글이 간다(`TextChatService:CanUsersChatAsync`).
    - 공개 서버에서는 참가자 누구와도 Roblox 친구가 아니다(`Player:IsFriendsWithAsync`).
    - 확인이 오류를 내면 경고를 남기고, 라이브에서는 그 사람을 뺀다. Studio에서는 통과시킨다(Studio에서 `GetChatGroupsAsync`는 "disabled" 오류를 낸다).
- **판 동안:** 진행자는 단상(`PoolHall.Podium` 위 3스터드)에 서고 걷기 `PRESENTER_WALK_SPEED`(0)·점프 0이다. 판이 끝나면 16 / 7.2로 돌린다. 새 캐릭터가 생기면 단상으로 다시 옮긴다. 모두에게 들리고(`refreshSpeakers`), 관전 처리(관람석 이동)에서 빠진다.
- **미션 메뉴:** 자유 대화의 마지막 `PRESENTER_PICK_SECONDS`(15)초에 진행자에게만 `PresenterMenu`가 간다(`{options = {id, title, recommended}, endsAt}`). 고르면 `PresenterPick`, 서버는 지금 메뉴에 있는 id만 받는다. 고른 미션은 자유 대화가 끝난 뒤 시작한다. 시간이 지나면 시스템이 추천 1순위를 고르고 "시간이 지나서 추천 미션으로 진행해요"를 띄운다. 연속 `PRESENTER_MISSES`(2)번 넘기면 진행자를 바꾼다. 상태를 다시 요청한(`Sync`) 진행자는 열린 메뉴를 다시 받는다. 마감이 지난 뒤 도착한 선택은 서버가 버린다. "시간이 지나서…" 알림은 진행자가 실제로 시간을 넘겼을 때만 뜬다(진행자가 바뀌어 메뉴가 닫힌 때는 안 뜸).
- **메뉴 순서(`MissionRunner`):** 남은 시간에 들어가고(`maxPerRound`·`minPlayers`를 지키는) 미션을, 이번 판에 적게 한 순서로 보여 주고 앞 3개에 "추천"을 단다. 진행자가 없거나 안 고르면 같은 순서의 1순위를 진행한다.
- **효과음:** 진행자 화면 아래에 두구두구·박수·웃음·딩동·땡. `PresenterSound`(번호) → 진행자·판 중·버튼별 `PRESENTER_SOUND_COOLDOWN`(3초) 검사 → 모두에게 `Sound` → 각자 `Fx.presenterSound`가 복사본을 재생한다. 복사본은 재생이 끝나면 지운다. 끝나지 않을 때를 위해 불러온 뒤부터 `max(8초, 음원 길이) × 2`, 끝내 못 불러오면 30초 뒤에 지운다(8.3초 두구두구가 잘리지 않게).
- **판 중 교체:** 퇴장, 연속 넘김, 지원 취소("진행 넘기기"). 생존자가 아닌 지원자(탈락자·관전자) 중 남은 생존자 기준으로 조건을 통과한 사람이 이어받고, 없으면 시스템이 진행한다. 날아가는 중인 사람과 이번 판에 이미 교체된 전 진행자는 후보가 아니다(전 진행자는 그 판이 끝날 때까지 관전자, 관람석으로 감). 조건 확인 중에 판이 끝나면 아무도 세우지 않고 변경도 알리지 않는다. 확인하는 동안 서버는 `Match.presenterPending`을 켜 두고(방송에 포함), 클라이언트는 그동안 알림을 미뤘다가 확인이 끝난 방송에서 한 번만 띄운다("진행자가 바뀌었어요: 이름" 또는 "진행자 없이 자동으로 진행해요").
- **결과:** 끝까지 진행한 사람에게 `SCORE_PRESENTER`(2)점, 결과 글 끝에 " · 진행 이름".
- **화면:** 진행자 카메라(`PoolHall.PresenterCamera`, 속성 `Fov` 55)로 의자 줄을 본다. 자기 캐릭터는 자기 화면에서만 숨긴다(`LocalTransparencyModifier`, 카메라 바로 앞을 가려서). 나중에 붙는 액세서리·도구도 `DescendantAdded`로 숨기고, 진행이 끝나면 되돌린다. 자기 머리 위 표시도 안 그린다. 남의 화면에서 진행자 머리 위는 하트 대신 "🎤 진행자". HUD 목숨 자리에 "🎤 내가 진행자". 진행 중에는 리액션 바를 숨기고 효과음 바를 보인다. 배정 때 모두에게 "오늘의 진행자: 이름".

## 작성자가 정한 기본값 (오너가 바꿀 수 있음)

- 진행자 카메라 각도는 맵 묶음 때 정한 `PresenterCamera` 그대로다. 단상이 의자 줄의 오른쪽 앞이라 의자 줄을 비스듬히 본다(먼 의자 쪽 사람이 작게 보임). 묶음 4에서 판정 화면과 함께 다시 본다.
- 참가자 쇼 카메라에는 진행자가 안 보인다(단상이 카메라 쪽에 있음). 진행자 목소리는 들린다.
- 지원 버튼은 판에서 뛰고 있는 생존자와 채팅 참가자에게 숨긴다(탈락자에게는 보인다 = 판 중 교체 후보).
- 물러나기 버튼 글은 "진행 넘기기"다. 처음 넣은 "진행 그만두기"는 "만두"가 단어장 단어라 문구 검사에 걸렸다.
- 넘김으로 교체된 진행자의 지원은 켜 둔다(다음 판에 다시 뽑힐 수 있음). 끄는 게 낫다면 오너가 정한다.
- 미션 메뉴의 추천은 3개, 메뉴에서 미션 이름 앞에 "★"와 뒤에 "· 추천".

## 시험한 방법

- **가상 시계 시험**(`round` 묶음 10번, 25개): 10a 지원자가 진행·의자 없음, 10b 모두에게 들림, 10c 진행자에게만 마지막 15초 메뉴, 10d 남의 선택·없는 미션 무시와 자유 대화 뒤 시작, 10e 효과음 권한·간격, 10f 넘김 → 시스템 선택(알림), 2번 → 진행 끝, 10g 그 뒤 안 들림, 10h 퇴장 → 참가 안 한 지원자로 교체, 10i 물러나기 → 자동 진행·관람석, 10j 진행 점수와 결과 문구, 10k 단상 고정과 판 뒤 해제, 10l 인원 부족, 10m 채팅 참가자 불가, 10n 라이브는 음성 준비 필요, 10o 공개 서버 친구 제외(비공개는 허용), 10p 음성 그룹, 10q 채팅 도달, 10r 확인 실패(Studio 허용·라이브 불가), 10s 순번(적게 한 사람부터), 10t 지원한 탈락자가 판 중에 이어받기, 10u 교체 확인 중에 판이 끝나면 아무도 안 세움(친구 확인을 4초씩 기다리게 함), 10v 교체된 전 진행자는 그 판에 다시 안 뽑힘, 10w 날아가는 사람은 못 이어받음, 10x 확인 중 채팅 참가로 바꾼 사람은 안 뽑힘, 10y 확인 중 `presenterPending`이 켜지고 끝나면 꺼짐. 10t~10x는 고치기 전 코드로 돌리면 실패하는 것을 하나씩 확인했다. 10d는 남의 선택·없는 미션 뒤에 메뉴 닫힘이 0건인지도 본다. 가짜 확인 함수가 즉시 돌아오는 경로가 많고 단상 위치(가짜 맵에는 단상이 없음)는 시험하지 않는다. 가짜 `GetChatGroupsAsync`·`CanUsersChatAsync`·`IsFriendsWithAsync`는 `tools/tests/prelude_server.luau`와 `round_tests.luau`의 가짜 플레이어에 있다.
- **정적 검사:** 새 문제 0건(`IsFriendsWith` → `IsFriendsWithAsync`, `UDim2.new` → `fromScale`/`fromOffset` 등 고침). **의존 방향:** 35개 모듈, 72개 require, 층 규칙·순환 없음.
- **Studio v3_chat 혼자:** 지원 버튼이 켜지고 꺼지는 것, 혼자 지원하면 뽑히지 않는 것(인원 부족), 콘솔 오류 없음.
- **Studio 2명(`StudioTestService:ExecuteMultiplayerTestAsync(2, {})`, 서버 창 + 클라이언트 창 2개, 새 창은 바로 최소화):**
    - QA용 짧은 타이머(카운트다운 60초, 자유 대화 25초, 본 게임 150초, 시험 미션 5초, 실패 확률 0)를 설치 뒤에 넣었다. 커밋하지 않는다.
    - 1회차: Player1이 판이 시작된 뒤에 지원해서 다음 판에 진행자가 됐다. 단상(걷기 0)과 Player2 착석, 진행자 화면의 "🎤 내가 진행자", 메뉴 "다음 미션을 골라 주세요 · 11 / ★ 연습 미션 · 추천", 효과음 바를 확인했다. 캡처가 느려 2번 넘겨서 교체 규칙도 실제로 돌았다. 고친 것: 진행자 화면을 자기 몸과 자기 머리 위 표시가 가림 → 자기 화면에서 숨김.
    - 2회차(고친 코드): Player1 클라이언트에서 지원 → 판 → 메뉴 도착 3초 뒤 `PresenterPick("test")`, 효과음 1, 0.5초 뒤 1(간격으로 버려져야 함)과 2. 기록: 메뉴는 본 게임 시작 10초 뒤(25 − 15) 열림, 선택 즉시 메뉴 닫힘, `Sound` 1과 2만 도착(두 번째 1은 버려짐), 자유 대화 뒤 연습 미션 시작. 다음 바퀴에서도 같았다. Player2 클라이언트에서 효과음 5개가 모두 불러와졌다(IsLoaded, 길이 위 표).
