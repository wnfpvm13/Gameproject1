- 지원 기기: 가로 화면 고정(PC·폰·태블릿). 세로는 막음.
- 되돌리기(절차):
    1. 게시 직전에 게시 장소의 PlaceId·현재 게시 버전 번호·경험 설정 값(공개 여부, 비공개 서버, 음성, API, 최대 인원)을 이 문서에 적어 둔다.
    2. 게시하는 커밋에 태그를 단다(게시본은 이 점검의 수정 커밋 — 태그 이름 예: `banned-words-v3-publish-1`). 1단계 완료 태그 `banned-words-v3-5b`(9ffdf0d)는 게시본이 아니다(그 뒤 다중 시험 수정 8550b29와 이 점검의 수정이 있음).

    4. 이전 버전이 없는 새 장소라면 경험을 비공개로 돌려 막는다.
    5. 코드만으로 이전 상태를 다시 만들 때는 그 태그에서 설치기(`tools/install_game.luau`)를 다시 만들어 실행하고, 그 태그의 맵 빌더(`build_pool_hall` → `build_pool_lighting`, V2는 `build_lounge_map` → `build_lounge_lighting`)를 돌린 뒤 게시한다. 경험 설정은 git에 없으므로 1번에 적은 값으로 되돌린다. 이전 태그: `banned-words-v3-5b`, `…-5a`, `…-4b`, `…-4a`, `…-3`, `…-2c`, V2 마지막 `banned-words-v2-final`.

## 확인한 것 (근거)

- **리모트 입력 검증(권한·형식·간격):** 클라이언트 → 서버 리모트 12개(`Ready`, `ChatJoin`, `Sync`, `DevFling`, `MissionAnswer`, `Rescue`, `EarJudge`, `Reroll`, `Volunteer`, `PresenterPick`, `PresenterSound`, `Reaction`)를 모두 서버에서 검사한다(`Net.listen` 목록 대조, Claude 검토자가 코드로 재확인). 각 묶음의 교차검증(Codex + Claude)에서 형식·권한·간격을 봤다.
    - 간격 제한 있음: `Volunteer`(1초), `ChatJoin`(1초), `Sync`(1초), `Reaction`(1.2초), `PresenterSound`(버튼별 3초), `EarJudge`·`Reroll`(진행자별 1초).
    - 상태로 막힘(간격 없음, 비용 작음): `MissionAnswer`(열린 문제·번호·마감·첫 답만), `PresenterPick`(진행자·열린 메뉴·목록에 있는 id), `Rescue`(진행자·대기 중인 hit).
    - Studio 전용: `DevFling`(라이브는 무시), 시험용 속성 `BW_ServerKind`·`BW_ChatAccess`(라이브는 무시, `RunService:IsStudio()` 확인), 시험 미션(Studio에서만).
    - `Ready`: 값이 바뀔 때만 처리하고, 방송은 0.5초에 한 번으로 묶는다(이 점검에서 고침, 아래).
    - 2단계 음성 인식용 `JudgeService`는 지금 실행되지 않는다(아무 모듈도 require하지 않음). 그 리모트들(`Settle`·`Transcript`·`VoicePing`·`Settled`)은 이 점검에서 닫았다.
- **비밀 유지:** 내 금칙어는 서버가 나에게 보내지 않는다(`WordService.payloadFor`, 시험 server 3e·3f, round 13b). 퀴즈 정답은 시간이 끝난 뒤에만 보낸다(mission 1a~1e). 채팅 제한 여부는 본인에게만(2c).
- **자동 시험:** `python -I tools/tests/run_tests.py` → speech·server·round·mission·deps 전부 통과(8550b29 + 이 점검의 수정, round 16a 포함). `python -I tools/lint/run_lint.py` → 새 문제 0건(알려진 8건은 기존).
- **실행 오류:** Studio(v3_chat) 혼자 실행과 2명·4명 다중 시험에서 서버 콘솔에 우리 코드 오류 없음(Studio에서 예상되는 `GetChatGroupsAsync is disabled` 경고만).
- **고정 문구:** `Config.TEXT` 전체가 단어장과 겹치지 않음(server 시험 4). 퀴즈 160문제·한마디 주제 60개는 검토자 두 명이 내용 검사(틀린 정답·민감 주제 고침).
- **남의 글 표시:** 우리 화면에 남이 쓴 글을 따로 띄우지 않는다(이름은 DisplayName만). 채팅은 Roblox 채팅으로만 보인다.
- **화면 방향:** 가로 고정(`LandscapeSensor`).

## 이 점검에서 고친 것

- **`Ready` 방송 묶기:** 클라이언트가 준비 값을 빠르게 번갈아 보내면 바뀔 때마다 모두에게 판 상태를 보냈다(방송 증폭, 두 검토자 모두 지적). 이제 값은 바로 반영하고 방송은 `READY_BROADCAST_DELAY`(0.5초)에 한 번으로 묶는다(마지막 값 유지). 시험 round 16a.
- **쓰지 않는 2단계 리모트 닫기:** 음성 인식 판정용 `Settle`·`Transcript`·`VoicePing`·`Settled`는 듣는 코드 없이 열려 있었다 → 2단계까지 만들지 않는다(`Net` 머리말에 다시 넣을 것을 적음).

## 경고 (게시는 가능하지만 알아 둘 것)

- **준비 완료는 클라이언트 말을 믿는다.** 음성이 없는 계정이 "준비됨"을 보내면 음성 참가자로 의자에 앉을 수 있다(방해 수준). 서버가 이미 아는 음성 계정 여부로 막을 수 있지만, "음성 확인이 실패하면 음성 없음으로 본다"는 오너 결정과 부딪혀 오너에게 묻는다.
- **성능 측정 없음.** 마이크로프로파일러·메모리 측정을 하지 않았다. 맵은 파트 수가 적고(맵 묶음 기록), 플라잉 체어 발사는 한 번에 몇 명뿐이라 위험은 낮다고 보지만 근거는 없다. 실기기(Galaxy S23+ 60fps, 저사양 안드로이드)에서 한 판을 돌려 보기를 권한다.
- **폰 화면 미확인:** 미션 카드는 화면 높이 80%·폭 90%로 줄어들게 했지만 실제 폰에서 보지 않았다. 판정 메뉴가 Roblox 점수판과 겹칠 수 있고, 낮은 화면에서는 커진 미션 카드가 효과음 버튼을 가릴 수 있다.
- **Platform Integrated Chat 일정:** 2027년 2월 자동 적용(끌 수 있음), 5월 필수. 그 전에 채팅 참가자·채팅 판정·전달 규칙의 대안이 필요하다(설계 7번).
- **공개 서버(1단계)는 금칙어 없이 미션만** 한다. 게임 설명에 "금칙어는 비공개 서버에서"라고 적는 것을 권한다.
