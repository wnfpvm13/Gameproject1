# 음성 받아쓰기 판정 실기 시험 — 준비와 순서 (2026-10-24)

6e(`docs/SPEECH_JUDGING_2026-10-23.md`, 태그 `banned-words-v3-6e`)로 받아쓰기 판정 코드는 들어갔다. 다만 로컬 Studio 시험(서버 + 클라이언트)에는 받아쓰기가 돌지 않는다. 그래서 실제 음성으로 정확도와 한도를 재고, 그 결과를 보고 오너가 `VOICE_JUDGING`을 켤지 정한다(설계 3번 표, 16번).

## 0. 두 가지 길

- **길 1 — Team Test(게시 없음, 먼저 권함):** Roblox 공식 튜토리얼은 받아쓰기를 Studio의 **Team Test**에서 시험하라고 안내한다(Test → Clients and Servers → Team Test → Start, 마이크 켜고 말하기; 단 장소가 한 번은 게시돼 있고 경험 설정에서 마이크가 켜져 있어야 함 — [튜토리얼](https://create.roblox.com/docs/tutorials/use-case-tutorials/audio/speech-to-text)). 시험 장소(84102094280848)는 이미 게시된 클라우드 장소이므로, 새 버전을 게시하지 않고 Studio 편집 상태 그대로 시험 서버에서 돌린다. PC 계정만 들어올 수 있다(폰 시험 H는 길 2). Team Test **서버**의 `RunService:IsStudio()` 값은 공식 자료끼리 다르다(API 표는 참, Roblox 직원 설명은 서버 거짓). 참이면 코드의 Studio 설정이 적용된다: 최소 1명, 준비 완료 필수 아님(A는 "마이크 확인 완료" 알림으로 본다), 서버 종류는 `STUDIO_SERVER_KIND`(공개 규칙; `workspace`의 `BW_ServerKind = "private"`로 비공개 규칙). 거짓이면 라이브와 같다: 최소 2명(혼자 시험판은 1명), 준비 완료 필수, Studio 속성 무시. 시작할 때 서버 콘솔에서 확인해 결과에 적는다.
- **길 2 — 시험 장소에 게시(오너 승인 뒤):** 폰(H)까지 보려면 시험판을 시험 장소에 게시한다. 공개하지 않은 채로 시험 계정만 들인다.
- **혼자 시험(오너 2026-10-24: 시험 계정이 오너 하나뿐):** 시험판을 `--voice-judging --solo`로 만든다(9절). 한 명으로 판과 금칙어 토크가 열리고 **자기 금칙어가 자기 머리 위에도 보인다** — 다른 계정이 알려 줄 필요가 없다. 볼 수 있는 것: A·B·C·D(남의 금칙어 항목은 빼고)·E·F·I(그리고 G의 혼자 몫). 못 보는 것: 여러 명의 혼선, 여러 명일 때 한도, 진행자(J), 폰(H, 길 2).
- 공개 전(비공개) 경험에서 음성·받아쓰기가 되는지는 공식 문서에 명시가 없어 **확인되지 않은 가정**이다. A(마이크 시험)가 그 관문이다.

## 1. 시험 전에 알아야 할 게임 규칙 (합격 기준이 이것에 맞춰져 있음)

- **자기 금칙어는 자기 화면에 안 보인다**("나만 몰라요"). 시험할 때는 다른 계정이 자기 화면에서 보고 **음성이 아닌 길**(메신저·메모)로 알려 준다. 걸리면 **새 단어로 바뀌므로** 다시 알려 줘야 한다.
- 걸리면 5초 동안 날아가고, 그동안은 판정하지 않는다. 다시 의자에 앉은 뒤 말한다.
- 목숨은 3개다. 2명일 때 한 사람이 세 번 걸리면 판이 끝난다. 그래서 "사람마다 몇 번"은 **여러 판에 걸쳐** 센다.
- **판정 규칙:** 정규화(문장부호·영문 대소문자 등) 뒤 금칙어가 **붙어 있는 그대로 들어 있으면** 걸린다(V2에서 오너가 정한 규칙, `src/shared/Judge.luau` 머리말). 예를 들어 금칙어가 "사과"면 "사과나무", "청사과"도 걸린다(정상). 띄어쓰기로 갈라지면("사 과") 안 걸린다.
- 판정은 **자기 마이크의 받아쓰기**만 본다. 같은 방 스피커로 남의 목소리가 내 마이크에 들어가면, 남이 말한 내 금칙어로 내가 걸릴 수 있다. **계정마다 다른 방에서, 헤드폰을 쓰고** 시험한다.
- **시간 경계:** 토크 대화 구간 안에서 **시작하고 끝난** 말만 센다(`END_TOLERANCE = 0`). 끝 직전에 시작했어도 끝을 넘겨 계속된 문장은 안 센다. 음성 감지가 늦게 꺼지는 꼬리 때문에 끝 바로 전에 끝난 문장도 빠질 수 있다 → E의 결과는 `END_TOLERANCE`를 정할 자료로 적는다.
- **서버 종류:** 비공개 서버가 아니면 공개 서버 규칙이다(공개 전 경험의 일반 서버도 마찬가지).
    - 진행자 후보가 참가자와 **친구면 진행자가 될 수 없다**. 시험 계정끼리 친구라면 친구가 아닌 진행자 계정이 필요하다.
    - 진행자 구제는 판당 1번이다. 귀 판정(주관 판정)은 같은 사람에게 판당 1번까지(다른 주관 판정과 합산), 마지막 목숨은 못 뺏는다.
    - 진행자는 참가자들과 음성 그룹도 같아야 뽑힌다(진행자 조건 확인).
    - 진행자가 없으면 다음 게임이 무작위라 금칙어 토크가 가끔만 나온다(한 판 8분). 시간을 넉넉히 잡는다.

## 2. 합격 기준

| # | 확인할 것 | 합격 |
|---|---|---|
| A | 마이크 시험 | 음성 참가자가 한 마디 하면 "마이크 확인 완료"가 뜨고 준비 인원이 오른다(라이브에서는 이게 안 되면 판이 시작되지 않음) |
| B | 금칙어 토크가 나옴 | 진행자 메뉴(또는 무작위)에 "금칙어 토크"가 있다 |
| C | 자기 금칙어를 말하면 걸림 | 대화 구간에서 (알려 받은) 자기 금칙어를 문장 속에 말하면 1~2초 안에 "땡"(진행자가 있으면 구제 띠, 없으면 바로 발사). 계정마다 **5번 이상 시도해 80% 이상**(5번이면 4번 이상) 걸림(여러 판에 걸쳐) |
| D | 잘못 걸리지 않음 | 금칙어와 받침·한 글자가 다른 말, 띄어쓰기로 갈라진 말, **남의** 금칙어를 말해도 안 걸림. 계정마다 5번 이상 시도해 **한 번도** 안 걸림. (금칙어가 들어 있는 더 긴 단어는 걸리는 게 정상) |
| E | 끝 무렵의 말 | 끝나기 2~3초 전에 시작해 끝나기 전에 마친 짧은 문장의 금칙어는 정산에서 걸림. 끝을 넘겨 계속된 문장은 안 걸림. 결과를 적음 |
| F | 정산 기다림 | 서버 콘솔 한 줄(3번)의 `settle waited`가 보통 1초 안. 5초(`SETTLE_MAX`)가 자주 나오면 원인을 본다 |
| G | 요청 한도 | 서버 콘솔에 `transcripts this minute (STT limit ...)` 경고가 없고, C의 실패나 전사 누락이 한도 때문으로 보이지 않음. **콘솔 숫자는 실제 받아쓰기 요청의 하한일 뿐**이다(마이크 시험, 마이크 시험을 안 한 대기실·관전자의 인식기, 버려진 전사, 다른 서버는 빠짐) → 시험 동안은 시험 계정만 접속. 10명 부하는 사람이 모일 때 따로 본다(한도: 경험 전체 분당 `1 + 5 × 동시 접속자`, 요청당 음성 10초까지 — [공지](https://devforum.roblox.com/t/full-release-speech-to-text-api/4357786)) |
| H | 폰(길 2만) | 갤럭시 S23+에서 C가 PC와 비슷하게 되고, 토크가 끝나면 인식기가 꺼진다(배터리·발열 이상 없음) |
| I | 오류 | 서버·클라이언트 콘솔에 `[BannedWords]` 오류가 없다 |
| J | (진행자가 있을 때, 선택) 구제와 함께 적용 | 음성 적발 → 진행자 구제 띠. 구제하면 목숨 그대로, 3초 안에 안 하면 1개 줄어듦. 구제를 기다리는 동안 같은 사람의 두 번째 적발은 합쳐짐. 정산 중 늦게 걸린 사람들은 정산이 끝날 때 함께 줄어듦 |

## 3. 서버 콘솔에서 보는 한 줄

받아쓰기 판정이 켜진 토크가 정산될 때마다 서버 콘솔(F9 → Server)에 나온다. **말한 내용은 기록하지 않는다(숫자만).**

```
[BannedWords] talk 3 speech: 42 transcripts received (with repeats) from 4 speakers, 40 judged in the talk, 2 word matches, busiest minute window 45, settle waited 0.4 s
```

- transcripts received: 판정이 열려 있을 때 살아 있는 사람이 보낸 것 중 빈도·길이 검사를 통과한 수(중복 포함).
- speakers: 그중 보낸 사람 수(동시 접속자 수가 아님).
- judged in the talk: 토크 시간 안의 말로 판정한 수.
- word matches: 금칙어가 들어 있던 수. **발사 수와 다를 수 있다**(이미 구제를 기다리는 중, 날아가는 중 등으로 RoundService가 버린 것도 셈).
- busiest minute window: 이 서버가 고정 60초 구간 하나에 받은 전사의 최대(앞 토크와 걸칠 수 있음, 요청 수의 하한).
- settle waited: 클라이언트들이 "보낼 말 다 보냄"을 알릴 때까지 기다린 시간(최대 5초).
- 이 줄은 `VOICE_JUDGING`을 정식으로 켠 뒤에도 남는다(계속 둘지는 오너가 정함).

## 4. 시험판 만들기

1. 오너: 시험 계정 준비 — 오너를 포함해 계정마다 **13세 이상 연령 확인 + 음성 사용 가능**(받아쓰기·음성 조건).
    - 길 1(Team Test)은 시험 계정이 **장소 공동 작업자(편집 권한)**여야 한다. 공동 작업에도 연령 확인 등 조건이 있고, **개인 소유 경험은 친구에게만 편집 권한을 줄 수 있다**([협업](https://create.roblox.com/docs/projects/collaboration)). 그러면 시험 계정끼리 친구라서, 공개 규칙에서는 그 안에서 진행자가 뽑히지 않는다 → 길 1은 **진행자 없이**(C·D·E·F·G·I) 하거나, Team Test 서버가 Studio로 취급되면 `BW_ServerKind = "private"`로 비공개 규칙을 써서 진행자(J)를 본다.
    - 길 2는 Creator Dashboard의 접근 관리(Playtest 초대 또는 편집 권한)로 들인다. 진행자(J)를 보려면 참가자와 친구가 아닌 계정이 필요하다.
2. 작성자: `python -I tools/install_game.py --voice-judging` → `.qa/install_game_stt.luau`. 성공하면 경로가 찍힌다. 실패(모르는 인자, Config 줄을 못 찾음)하면 아무것도 쓰지 않고 멈추므로, **그때 남아 있던 옛 `.qa` 파일을 설치하지 않는다.** 저장소의 `Config.VOICE_JUDGING`은 `false` 그대로이고 이 파일만 `true`다. Studio에서 실행하면 결과가 `[speech judging ON - live test build] game installed`로 시작한다.
3. 오너: Studio에서 시험 장소를 연다.
4. 작성자(Studio MCP): 맵이 없으면 `tools/build_pool_hall.luau` → `tools/build_pool_lighting.luau`, 그다음 `.qa/install_game_stt.luau`를 Edit에서 실행.
5. 오너가 장소에서 직접 맞출 것(스크립트로 못 바꿈, `docs/PUBLISH_CHECK_2026-10-23.md`). **바꾼 설정은 적어 둔다**(되돌리기용).
    - `TextChatService.ChatVersion = TextChatService`, `StarterGui.ScreenOrientation = LandscapeSensor`.
    - Platform Integrated Chat이 꺼져 있는지.
    - 경험 설정: 마이크·음성 채팅 켜기, "Chat & Voice Groups APIs" 켜기, 장소 최대 인원(예: 12~20, 음성은 100명 이하에서만).
6. 길 1: Team Test → Start → 시험 계정들이 Studio로 들어온다. 길 2: 게시 전 버전 번호를 적고 File → Publish to Roblox(공개하지 않음).

## 5. 순서 (계정 2명 이상; 진행자를 쓰면 친구가 아닌 계정으로 3명 이상)

1. 각자 다른 방·헤드폰으로 접속 → 음성 연결 → 한 마디(A). 준비 인원 확인.
2. 판 시작 → (진행자가 있으면) "금칙어 토크" 고르기 → "바로 시작"(B). 진행자가 없으면 토크가 나올 때까지 다른 게임을 한다.
3. 토크 준비 구간에 서로의 금칙어를 메신저로 알려 준다.
4. 대화 구간 60초:
    - C: 자기 금칙어를 문장 속에 말함. 걸리면 새 단어를 다시 알려 받고, 의자에 돌아온 뒤 계속.
    - D: 비슷한 말·띄어 쓴 말·남의 금칙어 말하기.
    - E: 끝나기 2~3초 전에 짧은 문장 하나, 다른 판에서는 끝을 넘기는 긴 문장 하나.
    - J(진행자가 있으면): 구제하기 / 안 하기.
5. 정산 뒤 서버 콘솔 한 줄을 적는다(F, G). 토크를 여러 번(판을 바꿔 가며) 반복해 C·D의 횟수를 채운다.
6. 길 2라면 폰 계정으로 4~5를 한 번(H).
7. 콘솔 오류 확인(I).
8. 결과를 적어 작성자에게: 계정별 C 시도/걸림, D 시도/잘못 걸림, E 결과, 콘솔 줄들, 폰 체감.

## 6. 끝나면 되돌리기

- **길 1:** 게시하지 않았지만, 시험판 스크립트가 클라우드 장소의 편집 상태에 남는다. **다음 게시 전에 반드시 기본판으로 재설치**한다: 작성자가 `python -I tools/install_game.py`로 만든 `tools/install_game.luau`를 Studio Edit에서 실행 → 결과에 `speech judging ON`이 **없는지** 확인.
- **길 2:** 위와 같이 기본판을 Studio에서 재설치 → 게시 → 기존 서버 종료(Creator Dashboard) → 다시 접속해 토크가 안 나오는지 확인. 또는 버전 복원: **열려 있는 Studio 편집 세션을 모두 닫음**(자동 저장이 복원을 덮지 않게) → Creator Dashboard 버전 기록에서 4-6에 적은 이전 버전을 복원 → Studio에서 장소를 **다시 열어** 복원본인지 확인(설치 결과 문구·`Config.VOICE_JUDGING`) → 게시 → 기존 서버 종료 → 재접속 확인([버전 기록](https://create.roblox.com/docs/projects/version-history): 복원은 자동 게시가 아님).
- 4-5에서 바꾼 경험 설정 중 시험만을 위한 것은 적어 둔 대로 되돌린다.
- 결과가 좋으면 `Config.VOICE_JUDGING = true`로 바꾸는 것은 오너 결정(커밋 + 다음 게시).

## 7. 개편(6a~6e)으로 바뀐 게시 표면 — 추가 점검

`docs/PUBLISH_CHECK_2026-10-23.md`는 개편 전 코드 기준이다. 개편으로 **새로 생긴** 리모트는 `Bell`·`TalkStart`, **바뀐** 것은 `MissionAnswer`·`PresenterPick`, **다시 연** 것은 `Transcript`·`Settled`다. 서버 검증(코드 근거):

## 9. 혼자 시험판 (`--voice-judging --solo`)

- 만들기: `python -I tools/install_game.py --voice-judging --solo` → `.qa/install_game_stt_solo.luau`. Studio 결과가 `[speech judging ON - SOLO live test build, own word shown] game installed`로 시작한다.
- 기본판과 다른 것은 Config 네 줄뿐이다: `VOICE_JUDGING = true`, `SHOW_OWN_WORD = true`(자기 단어도 보임), `MIN_PLAYERS = 1`, `TALK_MIN_PLAYERS = 1`. 저장소 기본값은 모두 그대로다. `SHOW_OWN_WORD`는 기본판에서 켜질 길이 없지만, 혼자 시험판을 그대로 게시하면 켜진 채 나간다 — 그래서 서버가 시작할 때 콘솔에 `SOLO speech test build` 경고를 찍는다. 토크 준비 문구 "내 머리 위 단어는 나만 몰라요"는 혼자 시험판에서는 무시한다.
- 혼자일 때 다음 게임 후보: 다른 미션은 모두 2명 이상이 필요해서, 라이브(길 2)에서는 퀴즈와 금칙어 토크(혼자 시험판에서 1명)뿐이고 같은 게임은 연달아 안 나와 번갈아 나온다. **Studio이거나 Team Test 서버가 Studio로 취급되면 연습 미션도 끼어든다**(30% 확률로 무작위 실패라 목숨이 빨리 준다). 토크는 **판당 2번까지**(`GAME_PER_ROUND`)라 그 뒤 그 판은 퀴즈(와 연습 미션)만 나오고, 판 끝 무렵에는 남은 시간 때문에 토크가 빠질 수 있다 → C의 5번 시도에는 판이 여러 개 필요하다.
- 혼자 판에서 **세 번째로 걸리면 탈락하지 않는다**: 마지막 한 명이 떨어지면 "그대로 결승으로 가요" 규칙(남은 목숨 0으로 생존)이 적용되고, 결승은 1명이라 건너뛰어 결과에 본인이 우승으로 나온다 → 그 판이 끝나고 다음 판. (퀴즈 답을 두 번 연속 안 하면 잠수로 탈락하고 결과는 우승자 없음.)
- 순서: 1절 규칙 중 "자기 금칙어는 안 보인다"만 빼고 그대로. 토크 준비 구간에 머리 위 자기 단어를 확인 → 대화 구간에 C·D·E → 정산 뒤 콘솔 한 줄(F·G).
- Studio 로컬 확인(2026-10-24, v3_chat, 서버 + 1명): 혼자서 금칙어 토크가 열리고 머리 위에 자기 단어("자전거")가 보임, 정산 때 콘솔 한 줄이 나옴(로컬이라 전사 0). 확인 뒤 v3_chat은 기본판으로 다시 설치함.
- 끝나면 6절대로 **기본판으로 재설치**(혼자 시험판이 남은 채 게시하면 자기 단어가 보이는 판이 나간다). 4-2의 주의(만들기에 실패하면 남아 있던 옛 `.qa` 파일을 설치하지 않음)는 이 파일에도 같다.
