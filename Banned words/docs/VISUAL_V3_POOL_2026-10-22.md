# V3 실내 수영장 맵 — 만든 기록 (2026-10-22)

후임 에이전트용 기록이다. 규칙과 맵 계약은 `docs/DESIGN_V3.md` 9~10번이 기준이고, 여기에는 어떻게 만들었고 무엇을 확인했는지만 적는다.

## 다시 만드는 법

1. Studio에서 장소를 연다(QA용은 `rojo build default.project.json -o .qa/<이름>.rbxlx`로 만든 사본).
2. Edit 데이터모델에서 `tools/build_pool_hall.luau` 전체를 실행한다(MCP `execute_luau` 또는 명령 창). `workspace.PoolHall`을 지우고 다시 만들며, `LoungeMap`·`PoolMap`·`Baseplate` 같은 옛 맵도 지운다. 끝나면 "PoolHall built: 10 chairs, … parts, … lights"를 돌려준다(2026-10-22 검토 반영 뒤: 파트 867개, 조명 16개, 그림자 조명 2개).
3. 이어서 `tools/build_pool_lighting.luau`를 실행한다(Lighting 서비스만 바꾼다).
4. 쇼 카메라 구도는 `ShowCamera` 위치에서 FOV 40~42로 본다(`ShowCamera`의 `HalfWidth`가 화면 폭에 들어오는 값).

## 주의

- **실제 장소에 아직 저장·게시하지 않는다.** 빌더는 V2 `LoungeMap`을 지우는데, 지금 코드(V2.1.2)의 `SeatService`·`GhostService`는 `LoungeMap`을 기다린다. 판 흐름 묶음(V3 서비스)이 들어간 뒤에 실제 장소에 맵을 넣는다. 지금은 `.qa/` 사본에서만 쓴다.
- 화면 가로 고정(`StarterGui.ScreenOrientation = LandscapeSensor`)은 `default.project.json`에 넣었다. 세로 화면에서는 쇼 카메라에 10명이 다 들어오지 않는다.

## 만들면서 알게 된 것

- **벽 방향:** `wallRun`의 프레임은 오른손 좌표를 지키느라 +Z가 홀 안쪽이다. 그래서 바깥쪽 오프셋은 음수다. 처음 판은 양수로 둬서 벽이 1스터드 안으로 들어왔고, 위쪽 파란 띠와 벽면이 같은 면에 겹쳐 깜빡였다(Claude 검토자 지적으로 고침).
- **조명 우선순위:** `Lighting.PrioritizeLightingQuality = false`. 품질이 내려갈 때 그림자보다 시야 거리를 지킨다(착수 구역이 쇼 카메라에서 95~130스터드).

- **V2 재질 변형(MaterialVariant)을 빼고 기본 재질만 쓴다.** `BW_Leather`(퀼팅)는 흰색으로 칠해도 회색으로, `BW_Carpet`은 빨간색이 밤색으로 보였다. 빌더는 이제 MaterialService를 건드리지 않는다(이전 실행이 만든 `BannedWordsMaterials` 폴더는 남아도 무해하다).
- **SurfaceGui 숫자:** `SizingMode` 기본값(고정 캔버스)이면 `TextScaled` 글자가 아주 작아진다 → `PixelsPerStud`로 바꿨다. 그래도 Studio 편집 화면 캡처에서는 쇼 카메라 거리(약 43스터드)에서 숫자가 그려지지 않았다(25스터드에서는 보임). 실제 게임 화면에서 다시 본다(`DESIGN_V3` 16번).
- **의자 젖힘 방향:** `Hinge.CFrame * CFrame.Angles(math.rad(80), 0, 0)`이 맞는 방향이다(앞이 들리고 등받이가 수영장 쪽으로 넘어감). 캡처로 확인했다. 실제 동작은 판 흐름 묶음의 클라이언트 Fx가 한다.
- **화면 비율:** MCP 캡처는 1920×908(약 2.1:1)이다. 세로 FOV 42면 가로 약 78도라서, 10개 의자 줄이 화면 폭의 약 72%를 차지한다.
- 쇼 카메라 화면에서 의자 앞 바닥(진행자 쪽)은 비어 있다. 단상은 가운데를 가리지 않게 오른쪽(x = -24)에 둔다.
