The Studio place includes corresponding native Part/WedgePart `.rbxmx` models. These use the same authored shapes/palette and stable asset IDs, but they are **native equivalents, not imported Blender meshes**. Source triangle counts do not describe Roblox native rendering cost. [runtime_manifest.json](runtime_manifest.json) records BaseParts separately, including invisible rig/root parts and excluding the two monster hitboxes added by the server.

Hornboar and Cleaver meet their 3,000–6,000 and 1,000–2,500 triangle source budgets. Ingredient models are cleaned fantasy shapes; Horn Core is ivory with a cyan core. ## Rig and animation

Hornboar has ten Blender bones: Root, Spine, Neck, Head, four legs, Horn and Tail. All mesh vertices bind to the rig; the FBX reimport checks the ten bones and ten actions: Idle, Walk, Run, Alert, ChargeWindup, Charge, Headbutt, HitReact, Stagger and Death. HornIntact and HornBroken are separate objects. One logical horn HP pool follows the Monster Bible; its rendered pieces share that binding.

The native runtime has nine Motor6Ds connecting ten joint nodes. `HuntingAnimator` poses these on the client from server state/timestamps, including walk/run, windup, attacks, hit reaction, stagger and death. Cleaver uses a right-hand/R6 Motor6D grip and server-timed swing presentation. These procedural V1 poses do not use uploaded FBX AnimationIds. Animation readability, rig deformation and visual/hitbox synchronization need actual Studio QA.

## Reproduce

Run from `MonCook/` with Blender and Python available:

```sh
blender --background --python art/blender/build_assets.py
python3 art/export_runtime.py
blender --background --python art/blender/validate_exports.py
blender --background --python art/blender/render_previews.py
rojo build default.project.json -o MonCook_Phase_1_Hunting.rbxlx
python3 tools/validate_hunting_artifacts.py --place MonCook_Phase_1_Hunting.rbxlx
```

`model_spec.py` owns the authored shapes, palette and coordinate mapping. Source assets preserve editability and exports preserve rig/action data. The native exporter creates welds, Motor6Ds, root references and Binding StringValues; no Roblox mesh upload is necessary to open the QA file.

Source previews were rendered and inspected at close, medium and far camera distances. The large ivory horn is readable in these Blender renders. They are **source renders, not Studio screenshots**. ## Binding and replacement

`HuntingAssetBinder` resolves `Binding` tags (`Root`, `GameplayContainer`, `HornIntact`, `HornBroken`, `Joint:<name>`). Config selects asset IDs; AI and loot do not reference visual paths. Visuals have no combat collision; invisible body/horn hitboxes are configured independently. Horn breaking hides intact objects, reveals the stump and disables the horn query hitbox.

For V2 imported meshes, retain the bindings/root contract or extend only the binder/animation presentation, then adjust configured geometry. Keep MonsterService/CombatService/LootService behavior and encounter/reward IDs unchanged. The runtime Horn hitbox follows the server root and approximates the animated horn; this needs Studio measurement before polishing animation further.
