## 2. 코드

- 새 shared 모듈 둘(서버·클라이언트가 같이 씀, 클라이언트 부품끼리는 require하지 않는 규칙 때문에 shared에 둠):
  - `Words` — 화면 위 표시·안내·알림 글자(샌드백 이름 포함; 차체에 칠한 영어 글씨는 장식이라 따로). 한국어 먼저, 다른 언어는 여기에 더한다(결정 11). 순수(로블록스 호출 없음)라 테스트가 읽는다.
    무기 이름도 `Config.Weapons[...].label`에서 `Words.Weapons`로 옮겼다.
  - `UiStyle` — 글꼴·색·테두리·판·튕김·흐려짐. 서버의 상자 이름표도 이것을 쓴다.
- 새 클라이언트 부품 `RideCard`(첫 판 조작 카드, 방문마다 한 번). `init.client`가 연결한다.
- 바꾼 부품: `RoundHud`(판 셋·상태 줄·큰 글자), `FeedHud`, `HealthBars`(방금 깎인 양), `WeaponHud`, `HomeRunShow`(글자 모양, 별 소리),
  `RoundAudio`(종·환호, 음악 버튼 "음악 ON/OFF"), `HitFeedback`(무기별 휙·맞음·날림·끝내기 소리), `DropShow`(줍기 소리), `SwingInput`(버튼 글꼴),
  `SoundBank`(`vary`, 안 쓰던 `playing` 삭제), 서버 `WeaponDrops`(상자 이름표).
- 테스트 8절(Words): 모든 무기 이름, 입력 방식마다 카드 4~6줄, 시계·알림·무기 문구. `python -I tools/tests/run_tests.py` → 121개 통과(새 6개),
  의존 검사 49모듈. 린트 새 지적 없음.

## 4. Studio 확인 (QA 창 TrainBrawl_QA3, 혼자 시험 모드)

- 난투 중 위쪽 판 셋(한글 굵게), 화면 아래 무기 이름·체력 숫자, 승리 큰 글자와 작은 글, 카운트다운 숫자, "출발!"(시간 0:25 금색),
  실제로 떨어졌을 때 "하차!"·상태 줄·때린 사람 없는 하차 알림(그때 문구 "발을 헛디뎌 하차", 검토 뒤 "B 하차"로 바꿈), 첫 판 카드(카운트다운 중)를 화면으로 봤다.
- 승리·카운트다운·출발 장면은 클라이언트에서만 판 상태 속성을 잠깐 바꿔 띄웠다(서버가 다음에 바꾸면 덮어씀). 하차는 실제로 떨어뜨렸다.
- **캡처 도구 주의 두 가지:**
  - MCP `screen_capture`는 UIScale을 그리지 않는다(크기 1로 그림). 카운트다운 숫자는 실제 창(PrintWindow)에서 커진 것을 확인했다.
  - 로블록스 글자 크기는 100픽셀이 최대다(TextSize 200을 넣으면 100). 그래서 카운트다운 숫자는 큰 글자를 UIScale 1.7로 키운다.
- 아직 못 본 것: 휴대폰 화면(카드·판 크기), 게임패드 카드, 소리의 실제 느낌, 두 명 이상.

## 5. 남은 어색한 곳(다음 묶음에서)

- 공격 자세가 오른쪽 어깨 하나만 돎, 3타째도 1·2타와 같은 잽(5b).
- 맞는 순간은 흰 번쩍임뿐, 날림은 뻣뻣하게 넘어짐(5c).
- 빨간·노란 Neon 원판, Sparkles, 유니코드 "✦" 별(5d). 모바일 "때리기"는 로블록스 기본 회색 원 버튼(글꼴만 바꿈, 5d).
- 샌드백 이름("샌드백 5")은 로블록스 기본 이름표(가는 글꼴) — 혼자 시험용이라 그대로 둠.
