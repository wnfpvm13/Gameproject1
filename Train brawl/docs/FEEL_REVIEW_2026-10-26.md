5단계(손맛·첫인상) 네 묶음 중 5b·5c·5d를 교차검증하고, 나온 지적을 한 번에 고친 기록. 5a는 앞서 검토가 끝났다.

## 1. 누가 검토했나

- 2026-10-26 오너가 바꾼 규칙: 검토는 Codex가 하고, Codex가 사용 한도를 넘으면 Antigravity가 맡는다. 중요한 작업이면 둘 다 한다.
- 5b는 게임 규칙을 바꿨다(날림을 때리는 사람의 연타가 정함, 서버가 클라이언트가 말한 단계를 어디까지 받을지). 그래서 중요한
  작업으로 보고 Codex와 Antigravity 둘 다 받는다. 5c·5d는 연출이라 한 검토자로 충분하다. Codex가 한도 초과라 Antigravity가 맡았다.
- Antigravity(`gemini-4-argon-high`, plan 모드·샌드박스, 읽기만)가 5b·5c·5d를 따로 보았다. 첫 실행에서는 경로 하나가 치환되지 않아
  세 묶음을 한 번에 보았고, 5d는 다시 돌렸다. 실행 전과 뒤에 HEAD·`git status`·stash·검토 폴더를 비교했다. 달라진 것은 실행 중에 내가 고친
  파일과, 다른 세션이 검토 폴더에 둔 MonCook 요청 파일뿐이었다(Antigravity가 쓴 것 없음).
- Codex의 5b 검토는 한도가 풀리는 23:40에 돌도록 예약했다. 결과가 오면 이 문서에 덧붙인다.

## 3. 바뀐 코드

- `OwnSwing`: `predict`의 결과로만 맞음, 서버 적중으로 이어 줌(재확인 뒤 `serverHit`), 무기가 바뀌면 연타 초기화, 예약된 판정은 고쳐진 단계를 읽음.
- `WeaponService`: 손의 무기가 바뀌면 연타 초기화.
- `init.client`: 서버 적중으로 연타를 이어 줌(연타 무기만), 내가 먼저 보여 준 효과선 종류와 더 큰 서버 판정의 효과선·멈칫(재확인 뒤 종류는 `OwnSwing`이 공격마다 가짐).
- `AttackPoses`: 동작의 관절 전체를 끝까지 그리기, 마지막 키 절반만 돌아오기(`SETTLE`).
- `HitFeedback`: 킥 겹침.
- `LaunchShow`: 착지 판정.
- `GroundMarks`: 깜박임, 테두리, 위에 그리기.
- `Dynamite`: 벽에 맞으면 바닥으로, 도화선 끝 불꽃.
- `WeaponDrops`: 줄·통풍구, 석탄차 제외.
- 그 밖: `WindDust`(평평한 지붕만, 재확인 뒤 만들지 않음), `CarDecor`(통로 색), `SwingInput`(터치 눌림), `Config` 주석.
- 테스트: `run_tests.py`에 `AttackPoses`, 11절 3개. 148개 통과, 의존 검사 56모듈, 린트 새 지적 없음.
- 문서: `DESIGN.md`(결정 13·15, 무기 상자 표, 핑 계산, 문서 목록), `README.md`.

## 4. Studio 확인 (QA 창, 혼자 시험, 동기화 56파일)

- **깜박임:** 6초짜리 경고를 놓고 매 프레임 안쪽 원을 읽었다. 1초마다 바뀐 횟수는 8, 11, 15, 17, 20, 18이었다(초당 약 4 → 10번 깜박임,
  60프레임 중 일부만). 고치기 전 공식이면 프레임마다 거의 무작위로 바뀐다.
- **벽에 맞은 다이너마이트:** 평판차에서 화물칸 뒷벽 쪽으로 서버에서 실제로 던졌다. 높이 약 14.3에서 벽에 맞고, 0.23초 만에
  평판차 바닥(10.3)에 떨어졌다. 경고 원도 바닥 높이(10.05)에, 벽에서 1 떨어진 자리에 놓였다. 불꽃은 도화선 끝 Attachment에 붙어 있다.
  처음 시험한 자리(벽에서 조금 먼 곳)에서는 벽을 넘어 화물칸 지붕에 떨어졌다. 이것은 정상이다.
- **경고 원 모양:** 실제 창(PrintWindow)으로 봤다. 원이 화물칸 벽 위로 그려져 가려지지 않고, 테두리가 끝까지 둥글다.
- **낙하산:** 떨어지는 상자를 복제해 공중에 멈추고 봤다. 줄 네 개가 덮개 밑면에 닿는다.
- **통로:** 화물칸 지붕 가운데 통로가 밝은 판자색으로 지붕과 구분된다.
- **착지 먼지:** 샌드백을 맨주먹 1·2·3으로 날렸다(스윙 원격을 직접 보냄). 18.2에서 20.1까지 떴다가 떨어졌고, 지붕에 닿아 튕기는
  순간(0.87초, 몸 16.5, 속도 +2.9) 지붕 높이(15.3)에 먼지가 나고 꼬리가 꺼졌다.
- **연타:** 클라이언트에서 `OwnSwing`을 가짜 원격으로 따로 만들어 실제 캐릭터·샌드백으로 눌렀다.
  - 보여 준 적중으로는 1, 2, 3이 된다.
  - 맞힐 수 없는 상대에게는 1, 1이다.
  - 화면에서는 빗나갔어도 서버 확인이 오면 1, 2로 이어진다.
  - 1을 맞히고 무기를 바꾸면 1, 1(처음부터)이고, 같은 무기면 1, 2다.
- **바람 알갱이:** 화물칸 가장자리를 낮게, 가까이서 봐도 거의 안 보였다(위 판단).
- **못 본 것:**
  - 홈런·협공으로 커진 내 타격의 효과선. 두 사람이 필요하다. 코드 경로만 확인했다.
  - 킥 겹침의 느낌.
  - 공격 자세의 실제 모습. 테스트로 관절이 빠지지 않는 것만 확인했다.
  - 폰에서 버튼을 직접 눌러 보기.

## 5. 남은 것

- 바람 알갱이를 다시 만든다. 지금은 효과가 거의 보이지 않는다. 다음 손맛 점검 때 선로 옆 풍경 속도와 함께 본다.
- 경고 원을 위에 그리면 원 안에 선 캐릭터의 발 위에도 겹친다. 위험 표시라 받아들였다.
- 벽에 맞은 막대가 튕겨 나올 때 한 프레임에 옆으로 약 0.7 순간 이동한다(바로 떨어지기 시작해 눈에 잘 띄지 않음).
- 막대가 벽을 따라 떨어지는 중에 도화선이 끝나면 경고 원이 그 공중 높이에 그려진다(터지는 자리가 거기라서).
- 방망이를 다 쓰고 같은 무기를 0.9초 안에 다시 주워 누르면, 화면만 연타를 이어 그렸다가 서버 단계로 고쳐진다(P3, 아래 표).

P1·P2를 고쳤으므로 규칙대로 같은 검토자에게 한 번 재확인을 받았다. 실행 전후 저장소·검토 폴더 상태는 같았다. P1 둘과 P2 대부분은
"고쳐짐"이었고, 아래가 남았다. 재확인은 한 번뿐이라 아래를 고친 뒤에는 다시 받지 않았다. 5b 쪽은 23:40 Codex 검토가 함께 본다.

| 지적 | 등급 | 판단과 고친 것 |
|---|---|---|
| 서버가 3번째를 1로 고치면 화면의 "닿을 시각"이 0.08초 늦은 채로 남는다. 핑이 낮으면 서버 적중 알림이 앞 공격 것으로 오인돼 무시됨 | P2 | 동의. 시간으로 걸러내는 방식을 버렸다. 서버가 적중 알림에 그 공격의 시작 시각(`SwingAt`)을 실어 보내고, 화면은 그 시각이 마지막 공격(0.25초 안)일 때만 이어 준다(`OwnSwing.serverHit`) |
| 같은 경우 서버 알림이 화면의 예약된 판정보다 먼저 오면 소리·번쩍임·킥·효과선이 두 번 난다 | P2 | 동의. 먼저 온 알림의 대상은 기억해 두었다가, 예약된 판정이 그 대상은 다시 보여 주지 않고 맞은 것으로만 센다 |

| 벽에 맞은 다이너마이트가 네 가지로 어긋난다. 경고 원은 최종 바닥에 있는데 실제로는 도화선이 끝난 자리(아직 떨어지는 중일 수 있음)에서 터진다. 기차 사이 모래로 떨어지면 원이 모래 바닥에 그려진다. 보일러의 둥근 윗면도 벽으로 본다. 떨어지던 속도가 0이 된다 | P2 | 동의. 경고 원은 터지는 자리(도화선이 끝날 때 막대가 있을 곳)에 둔다. 모래 바닥이면 원을 그리지 않는다(거기서는 아무에게도 닿지 않음). 거의 수직인 면(위쪽 성분 0.3 미만)만 벽으로 본다. 떨어지던 속도는 이어받는다 |

| 무기를 다 쓰고 같은 무기를 바로 다시 주우면 화면은 연타를 잇는다 | P3 | 그대로. 0.9초 안에 상자를 주워야 생기고, 서버 단계로 곧 고쳐진다 |
| 거의 안 보이는 바람 알갱이를 켜 둔 것은 입자 낭비다 | P3 | 동의. 다시 만들 때까지 만들지 않는다(`init`에서 부르지 않음) |

Studio 확인(재확인 뒤 수정):
- 다이너마이트 세 경우를 서버에서 실제로 던졌다. 세 경우 모두 경고 원과 터지는 자리가 같다.
  - 화물칸 뒷벽: 평판차 바닥으로 떨어져 터짐, 원은 바닥에.
  - 옆 기차 지붕 가장자리: 그 지붕에 떨어짐.
  - 평판차에서 옆 기차 승무원차 옆벽: 높이 12.5에서 맞고 떨어지던 속도대로 6.2를 지나 모래까지 떨어짐, 원은 없음.
- 적중 알림 짝 맞추기를 가짜 원격으로 확인했다. 클라이언트에서 `OwnSwing`을 따로 만들어 실제 캐릭터와 샌드백으로 시험했다.
  - 화면이 보여 준 뒤 온 알림: 보여 준 종류("light")를 돌려준다.
  - 화면보다 먼저 온 알림: 화면은 그 대상을 다시 보여 주지 않고(예측 0번), 연타는 1, 2, 3으로 이어진다.
  - 앞 공격의 알림: 아무것도 바꾸지 않는다(1, 1).
- 테스트 148개 통과, 의존 검사 56모듈, 린트 새 지적 없음.
