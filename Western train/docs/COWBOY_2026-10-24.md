# 지붕 위 카우보이: 만든 기록 (2026-10-24)

후임 에이전트용 기록이다. 결정과 규칙은 `docs/DESIGN.md`(결정 12, 4번 "카우보이 단계")가 기준이다. 앞선 기록은
`docs/BRIDGES_2026-10-24.md`(흘러오는 다리).

## 무엇을 만들었나

오너가 "넘어가자"라고 해서, 2번 설계의 지붕 위 카우보이 중 기본만 먼저 만들었다.
- **화물칸:** 기관차 뒤에 화물칸 2량(붉은 판자 몸체, 어두운 테·문틀, 쇠 지붕과 가운데 판자 통로, 한쪽 4바퀴). 기관차와 같이
  납작해지고, 지붕 높이(7.7)가 운전실 지붕과 같다. 운전실 지붕과 첫 칸 사이(뒤로 뻗은 다리 위)는 좁은 판자 다리로 잇는다.
- **역할:** 들어온 순서로 짝을 짓는다. 첫 사람이 운전, 다음 사람이 그 기차의 카우보이다. 운전사가 나가면 카우보이가 운전사로
  다시 태어나고 기차를 새로 만든다.
- **카우보이:** 마지막 칸 지붕에서 시작한다. 지붕이 납작해지면 같이 내려가며 자동으로 엎드린다(높이 약 1.4라 다리 밑 5를 지남).
  공중에 있거나 서 있을 때 다리가 지나가면 "철퍽!" 하고 뒤로 날아가고, 1.2초 뒤 마지막 칸 지붕으로 돌아온다. 지붕에서
  떨어져도("앗!") 같다. 얼굴 창에는 운전사의 얼굴과 점수가 보인다. 카우보이에게는 S(납작) 키가 걸리지 않아 뒤로 걷는다.
- **혼자 시험:** Studio에서 Workspace 속성 `WesternTrainSoloCowboy`를 켜면 혼자 들어온 사람이 카우보이가 되고, 기차(그 사람 아바타로
  만든 것)는 봇이 대신 운전한다(다리 앞 8스터드에서 납작, 지난 뒤 2스터드에서 폄). `RunService:IsStudio()`일 때만 통한다.
- 아직 없는 것: 우편 주머니, 굴러오는 통, 기관차 점프와 같이 뛰기, 철퍽 때 종이처럼 납작해지는 연출, 모자 연출, 체크포인트
  구간, 짝 고르기(파티·초대·역할 바꾸기).

## Studio에서 알아낸 것

- **요즘 아바타의 관절은 Motor6D가 아니라 AnimationConstraint다**(`LowerTorso.Root`). 처음에는 Motor6D만 찾아서 아무 일도 안
  했다. 둘 다 `Transform`이 있어 같은 방식으로 쓸 수 있다.
- **애니메이터가 매 단계 관절을 쓴다.** RenderStepped에서 쓴 `Transform`은 그려지기 전에 덮어써졌고, `RunService.Stepped`에서 쓰면
  보였다. (이 관절의 C0를 바꾸려 하자 "읽기 전용" 오류가 났다.)
- 엎드린 자세 측정: 앞으로 90° 돌리면 몸이 뿌리(HumanoidRootPart)보다 약 1.1 아래에 눕는다. 뿌리는 지붕 위 3이므로 1.4 더 내리면
  지붕 위에 붙는다. 실제로 지붕 위 −0.13~1.38(꼭대기 4.69 < 다리 밑면 5).
- 지붕 따라 옮기기 기록: 납작(지붕 3.1) → 출렁임(지붕 9.2까지) → 원래(7.7) 동안 뿌리가 늘 지붕 + 3.0(날아가지 않음).
- 화물칸이 생기자 운전사 카메라(기차 가운데를 봄)가 화물칸 위에 떠서 기관차가 멀어졌다 → 카메라 초점을 기관차 가운데로 옮겼다.
- 보이지 않는 지붕 바닥은 충돌이 켜져 있어도 Roblox 카메라가 벽으로 보지 않는다(투명하면 가리는 물체로 치지 않음). 카메라 거리 26 유지 확인.

## 남은 것

- 운전사가 나갈 때 카우보이가 운전사로 바뀌는 것은 두 사람 시험에서 아직 안 해 봤다(`CrewBook` 테스트로 규칙만 확인).
- 카우보이의 철퍽·떨어짐은 카우보이 클라이언트가 판정한다(협동 게임이라 서버 확인 없음). 점수에도 아직 안 들어간다.
- 철퍽은 지금 뻣뻣하게 날아가는 것뿐이다(설계의 "종이처럼 납작"은 아직).
- 카우보이는 보일러 위를 걸을 수 없다(바닥 없음 → 떨어지면 마지막 칸으로).

## 교차검증 (Codex + Claude 검토자, 1회씩)

- Codex: P1 1건, P2 5건. Claude 검토자: P1 없음, P2 2건, P3 여러 건. 둘 다 짚은 것은 봇 기차 경쟁.
- 고친 P1·P2:
  - 봇 기차 빌드가 기다리는 사이 사람이 운전을 넘겨받으면, 늦게 끝난 봇 빌드가 사람의 새 기차를 지울 수 있었다 → 빌드가 끝난 뒤
    역할을 다시 확인(`buildTrain`의 `stillWanted`).
  - 철퍽 중에 기차가 바뀌면 카우보이가 굳은 채로 남았다 → `CowboyRules.stop`.
  - 운전실 지붕과 첫 칸 사이에 약 3스터드 틈이 있어 걸어서 못 건넜다 → 판자 다리.
  - R6 카우보이는 발밑 지붕을 못 찾았다 → 다리 길이 2를 더함.
  - 리스폰 때 S 키를 풀었다 다시 묶어 누르고 있던 키를 잃었다 → 카우보이가 될 때만 풂.
  - 다리 판정에 좌우 검사가 없었다 → 다리 폭 안에서만.
  - 떨어짐 판정이 뿌리 높이라 키 큰 아바타는 못 잡았다 → 발 높이로.
- 고친 P3: 바닥 위 판자에 발이 묻힘(바닥 윗면 = 통로 윗면), 판정 여유를 `Config.Cowboy.BridgeMargin`으로, `CrewBook`에 두 번 들어오기
  방어, 승격 때 `LoadCharacter`를 pcall로, 혼자 시험 속성은 Studio에서만, 얼굴 창은 기관차만 복사(화물칸·바닥 제외), 다른 사람
  카우보이는 발밑을 3 더 멀리 찾음(복제 지연), 사라진 캐릭터의 관절 정리(`IsDescendantOf`), 재시작 거리(아래), 서버·클라이언트가
  같이 쓰는 "바닥 위 자리"(`PartUtil.aboveFloor`), 문서와 주석의 낡은 문장.
- 재시작 거리: 달리기 거리가 기차 가운데 기준이라 화물칸이 붙자 재시작 뒤 앞코에서 다리까지가 약 18스터드(0.75초)로 줄었다(Claude
  지적). 60으로 늘려 약 38스터드(1.6초)로 되돌렸고, 테스트에 위 한계(앞 다리가 기차 뒤로)와 아래 한계(1.2초 이상)를 넣었다.
- 남긴 P3: R6 엎드린 자세의 축은 맞추지 않았다(R15 기준), 칸이 꽉 찬 뒤 들어온 사람은 나중에 칸이 비어도 배정되지 않는다,
  `BotDriver`의 달리기 읽기가 클라이언트 `RunTracker`와 비슷한 코드(서버·클라이언트라 따로 둠), 화물칸으로 늘어난 부품을 애니메이터가
  매 프레임 다시 씀(모바일 측정 필요), `Main`이 연결보다 커지고 있음(역할 처리를 나눌지 나중에).
- Codex 재확인(1회): 일곱 건 중 여섯 건과 재시작 거리 변경은 바르게 고쳐졌다. 남은 P2 1건 — 새 기차가 옛 기차보다 먼저
  카우보이 기차로 잡히면 옛 규칙의 굳은 상태 해제가 빠짐 — 은 탈 기차를 바꾸기 전에 옛 규칙을 먼저 정리하도록 고쳤다(재확인은 규칙상
  1회라 다시 받지 않음).
