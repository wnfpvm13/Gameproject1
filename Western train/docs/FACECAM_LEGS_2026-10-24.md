# 얼굴 창과 팔·다리 보이기: 만든 기록 (2026-10-24)

후임 에이전트용 기록이다. 결정과 모양 규칙은 `docs/DESIGN.md`(결정 10, 3·4번)가 기준이다. 앞선 기록은
`docs/LOCO_DRESSED_2026-10-23.md`(기관차 몸체, 보일러 색).

## 왜 했나

"아바타 옷을 입은 기관차"를 검토할 때 검토자 둘이 짚은 모양 문제가 두 가지 남아 있었다.
- 플레이 카메라(뒤·위)에서는 얼굴이 안 보인다.
- 팔(연결봉)은 검은 소매가 검은 바퀴에 묻혔고, 신발 범퍼는 블록 몸 발이 그냥 네모라서 신발로 안 읽혔다.

오너가 "둘을 먼저 고치고, 다음 단계로 넘어가자"라고 해서, 앞서 보고한 추천안대로 반영했다. 운전실 창문은 이 두 문제와
관계가 없어 넣지 않았다.

## 무엇이 바뀌었나

| 모듈 | 바뀐 것 |
|---|---|
| `client/FaceCam`(새) | 화면 위 가운데의 나무 테 + 황동 테두리 창. 내 기관차를 앞에서(약간 오른쪽·위) 비추고, 납작한 동안 커졌다가(0.15초) 떼면 통통 튀며 돌아온다(0.45초, Back). |
| `client/init` | 내 기관차가 오면 `faceCam:show`, 없어지면 `hide`, 입력마다 `setBig`, 매 프레임 애니메이터 다음에 `faceCam:update()` |
| `client/LocomotiveAnimator` | 다리 부품(`KickPivot`·`KickSide`)을 엉덩이를 축으로 X축 회전. 엉덩이 점도 몸과 같이 눌린다. |
| `shared/SquashPose` | `kickAngle(velocity, side, bodyY, limits)`: 스프링 속도 × gain, 양쪽 반대. 위로는 `up`까지, 아래로는 `down` × 남은 높이 비율(완전히 납작하면 0)까지 |
| `server/LocomotiveBuilder` | 손 = `HandSize`(1.3) × `HandLength`(0.8) 주먹을 앞 크랭크 핀 위치에(팔은 주먹 길이의 절반만큼 짧아짐). 다리 = 허벅지 + 정강이를 `LegLength`(2.4)로 늘려 허리 높이(`DeckHeight + CabWaist/2` = 2.5)에서 뒤로, 끝에 신발. 팔·다리 늘이기는 `stretchedLimb` 하나로. 바퀴 = 쇠 테(`Wheel`) + 짙은 빨강 가운데(`WheelCentre`, 테보다 양쪽 0.02 튀어나옴) |
| `shared/Config` | `Squash.LegKickGain` 0.07·`LegKickUp` 0.7(약 40°)·`LegKickDown` 0.35(약 20°), `Locomotive.HandSize`·`HandLength`·`TyreThickness`·`LegSpread`·`LegLength`·`LegThickness`(옛 `BufferHeight`·`BufferSpread`·`ShinLength` 대신), `Colors.Wheel`(140, 40, 30), `Config.FaceCam` 새 절(크기·시점·하늘·조명) |
| `shared/Names` | `AvatarHead`("Head", 빌더와 얼굴 창이 같이 씀), `KickPivot`, `KickSide` |
| `tools/tests` | 다리 흔들기 7개: 멈추면 0, 양쪽 반대, 한계, 완전히 납작하면 아래로 안 감, 실제 스프링 값으로 누를 때 30° 이상 차기, 뗄 때 위아래로 펄럭임, 신발이 선로 아래로 안 내려감. `run_tests.py` 앞부분에 `Vector3.new` 대역 추가(Config에 방향 값이 생김) |

## 얼굴 창에서 알아낸 것 (Studio에서 확인)

- ViewportFrame은 자기 안의 물체만 그린다. 그래서 기관차의 움직이는 부품(`RestCFrame` 속성이 있는 것)을 복사해 넣고, 매 프레임
  진짜 부품의 `Size`·`CFrame`·`Transparency`(FileMesh면 `Scale`도)를 따라 옮긴다. 값이 같으면 쓰지 않는다.
- **아바타 몸은 모델 통째로 복사해야 옷이 나온다.** 몸 부위만 하나씩 복사하면(Humanoid가 있는 모델에 넣어도, R15로 바꿔도,
  WorldModel에 넣어도) 셔츠·바지가 빠지고 맨살 색이 나왔다. 아바타 모델 전체를 `Clone`해서 창 안의 `WorldModel`에 넣으니 운전실
  재킷과 소매가 나왔다(`.qa/captures/v4_facecam_legs/qa_clothes_parts_only.jpg` ↔ `qa_clothes_whole_avatar.jpg`). 복사본에서는
  스크립트(PlayerGui 안에서는 LocalScript가 돌 수 있음)·소리·파티클을 지운다. 이 문제는 Codex 검토(P2)가 짚었다.
- **텍스처에 얼굴이 든 머리(동적 머리, 요즘 아바타 대부분)는 ViewportFrame 안에서 피부색이 빠지고 하얗게 나온다.**
  - 시험한 것: 그대로 복사, 투명도 0.02, 재질 변경, WorldModel 안, Humanoid가 있는 Model 안, 아바타 통째 복사. 모두 하얗다.
  - 텍스처를 지운 복사본만 몸 색(이 시험 아바타는 연보라)이 나왔다.
  - 그래서 머리 복사본만 위 겹 ViewportFrame(`FaceView`, `ZIndex` 2, 배경 투명, 같은 카메라)에 두고, 그 창의 `ImageColor3`를
    머리 색으로 물들인다. 하얀 피부는 피부색이 되고 검은 눈·입은 검은 채로 남는다. 아바타 통째 복사본의 머리는 숨긴다.
  - 한계(시험한 머리는 하나): 물들이기는 머리 그림 전체에 곱해져서 흰자·이·색 있는 입술도 피부색이 된다(피부가 어두우면 흰자가
    안 보임). 텍스처에 피부색이 이미 칠해진 머리는 두 번 곱해져 어두워진다. 텍스처가 없는 클래식 머리(데칼 얼굴)는 물들이지 않는다.
  - 앞에서 보면 머리가 가장 앞에 있어서, 머리 창을 위에 그려도 똑같아 보인다. 다만 아래쪽 앞 범퍼 빔과 화면에서 조금 겹치면
    머리가 빔을 덮을 수 있다(작음).
  - 비교 캡처: `.qa/captures/v4_facecam_legs/qa_white_skin_problem.jpg`(가운데·좌우 머리 = 하얗게 나온 시험 복사본).
- 조명: ViewportFrame 기본값(Ambient 200, 빛 140 회색)과 처음 넣은 값(Ambient 150, 거의 흰 빛)은 밝은 피부를 하얗게 날려서
  Ambient (105, 105, 110), 빛 (185, 178, 165)으로 낮췄다. 빛 방향은 기관차 기준이라 `show` 때 기관차 방향으로 돌린다.
- 창 위치: 왼쪽 위는 채팅, 오른쪽 위는 PC 플레이어 목록, 오른쪽 아래는 모바일 점프·납작 버튼, 왼쪽 아래는 모바일 이동 막대라서
  위 가운데(Roblox 상단바 바로 아래 8픽셀)에 두었다. 크기는 화면 높이의 20%, 납작할 때 30%(처음 22%·36%였으나, 뒤에서 보는
  카메라에서 앞쪽 선로를 가리지 않게 줄임). 다음 단계에서 다리가 다가올 때 가리는지 다시 본다.

## 남은 것

- 바지가 검은 아바타는 다리가 검은 운전실과 섞인다(이 시험 아바타). 신발 밑창(범퍼)은 회색 네모라 신발로 읽히는 정도는 아바타 옷에 따라 다르다.
- 소매가 빨간 아바타는 빨간 바퀴 위에서 팔이 덜 보인다(주먹은 피부색이라 보임).
- 얼굴 창은 내 기관차만 보여 준다. 나중에 카우보이 화면에 친구 얼굴을 띄울지는 정하지 않았다.
- 모바일 실기기에서 창 크기·위치, 펼친 채팅과의 겹침, ViewportFrame 비용(부품 약 50개 + 아바타 복사본)을 아직 보지 않았다.
