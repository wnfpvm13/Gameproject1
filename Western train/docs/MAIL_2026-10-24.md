# 우편 주머니: 만든 기록 (2026-10-24)

후임 에이전트용 기록이다. 결정과 규칙은 `docs/DESIGN.md`(결정 13, 4번 "우편")가 기준이다. 앞선 기록은
`docs/COWBOY_2026-10-24.md`(지붕 위 카우보이).

## 무엇을 만들었나

오너가 "다음 단계 하나씩 작업 시작해"라고 해서, 카우보이 다음 단계 중 첫째인 필수 우편 주머니를 만들었다.
- 다리 사이마다(다리 i와 i+1의 가운데) 선로 옆에 우편 크레인이 서 있다. 오른쪽·왼쪽이 번갈아 나온다. 나무 기둥에서 팔이 지붕 쪽으로
  뻗어 있고, 밧줄 끝에 둥근 천 주머니가 매달려 있다.
- 주머니는 지붕 끝 바깥(가운데에서 3.4; 지붕 끝은 2.6), 서 있는 카우보이의 가슴 높이(철로 위 11.1, 윗몸통 높이)에 있다. 그래서 지붕
  가운데나 판자 통로에서는 안 닿고, 그쪽 끝 가까이 서야 닿는다(윗몸통에서 1.6 안). 납작한 지붕에 엎드려서는 못 줍는다.
- 주우면 "우편!"과 함께 그 주머니가 사라지고, 점수에 "우편 N"이 붙는다(카우보이가 있을 때만, 실제로 주운 수).
- 못 주운 채 주머니가 기차 뒤로 지나가면 "우편 놓침!"이 뜬다. 1.4초 뒤 그 크레인 앞 다리의 재시작 지점(충돌 재시작과 같은 곳)에서
  다시 달린다. 다리와 크레인을 다시 지나는 "구간 다시"다.
- 카우보이가 없는 기차에는 주머니가 없다(크레인만 있고, 지나친 크레인은 우편 수에 안 들어감).

## 모듈

| 모듈 | 바뀐 것 |
|---|---|
| `server/MailService`(새) | 기차마다 다음 주머니(`MailNext`)·실제로 주운 수(`MailTaken`). 줍기 보고는 그 주머니가 앞코−6부터 놓침 판정 직전까지 기차 옆에 있을 때 받음. 주머니가 기차 뒤로 지나가고 `ReportTimeout`(1.5초) 뒤에도 안 주웠으면 놓침 → `onMissed`. 카우보이가 없으면 지나간 크레인을 그냥 넘김(수에 안 넣음) |
| `server/CourseService` | 다리 충돌의 "멈춤 → 되돌아감"을 `hold`로 일반화하고, `missMail(train, index)`을 공개(`MissedMail` 속성, 다리 index의 재시작 지점으로, 다음 다리는 거기서 다시 계산) |
| `shared/TrainState`(새) | 기차 속성 읽기: 달리기 시계(`run`)와 카우보이 유무(`hasCowboy`). `MailService`·`BotDriver`·`RunTracker`·`CowboyRules`·`CourseView`·`init`에 흩어져 있던 같은 코드를 모음 |
| `server/Main`, `server/Net` | `MailService` 연결(놓침 → `course.missMail`), `Mail` 리모트 |
| `shared/CourseMath` | `mailAt(i)`: 크레인 거리와 쪽 |
| `client/CourseView` | 크레인 그림(기둥·팔·밧줄·주머니·끈), 주머니는 카우보이가 있고 아직 안 주운 것만. 다시 그릴지 판단에 다음 주머니·카우보이 유무를 넣음 |
| `client/CowboyRules` | 다음 주머니와 내 윗몸통 거리로 줍기 판정 → "mail" 이벤트(한 번 알리고, 서버가 안 세었으면 1초 뒤나 달리기가 바뀐 뒤 다시) |
| `client/init` | 줍기 → `Mail` 리모트 + "우편!", `MissedMail` → "우편 놓침!"(운전사·카우보이 모두), 점수 갱신 |
| `client/FaceCam` | 점수에 우편(카우보이가 있을 때). 점수 글자를 창 오른쪽에 맞춰 왼쪽으로 늘어나게(길어지면 화면 밖으로 잘리던 것), 알림 글자 폭을 창 안으로 |
| `shared/Config`, `shared/Names` | `Config.Mail`, `MailRemote`, `MailNext`, `MailTaken`, `MissedMail` |
| `tools/tests` | 우편 7개(크레인 위치·번갈아, 가운데·판자 통로 끝에서 안 닿음, 지붕 끝 가까이에서 닿음, 엎드려 안 닿음, 기둥이 납작한 기차에서 떨어짐) → 80개 |

## 시험한 방법과 결과

- 테스트 79개(검토 반영 뒤 80개) + 의존 검사 통과, 린트 새 지적 0건, Rojo 빌드 → QA 창 Play Solo(혼자 시험 모드: 카우보이 + 봇 운전), 콘솔 오류 없음.
- 서버 기록기: 지붕 가운데에 서 있으면 첫 주머니(오른쪽)를 놓침 → `MissedMail=1` → 1.4초 뒤 재시작(앞 다리 다시 통과) → 또 놓침.
  오른쪽 끝(x 1.96)으로 옮기자 줍기(`MailNext=2`, `MailTaken=1`), 다음 주머니(왼쪽)는 놓침 — 모두 맞는 동작.
- 캡처(저장소 밖, `.qa/captures/v7_mail/`): `1_mail_crane_passing.jpg`, `2_cowboy_view_crane.jpg`, `3_score_with_mail.jpg`.
- QA 창을 최대화해서 찍었다(오너 허락: QA 창 띄우기).

## 남은 것

- 금화 우편(높이 매달림, 기관차 점프와 같이 뛰어야 닿음)은 점프 단계에서.
- 줍기는 카우보이 클라이언트가 판정하고 서버는 "기차 가까이"만 본다(협동 게임이라 이 정도).
- "구간 다시"는 지금 크레인마다다(설계의 20~30초 체크포인트 구간은 나중).
- 놓친 순간 카우보이가 철퍽·떨어짐으로 지붕에 없었어도 똑같이 놓침이다(설계대로).

## 검토 반영 뒤 다시 시험

- 지붕 가운데에 서 있으면 첫 주머니를 놓침 → 재시작 지점 90(= 다리 1의 150 − 60) → 다리 1을 다시 통과. 오른쪽 끝(윗몸통 x 2.49,
  높이 바닥 위 3.09)에 서자 오른쪽 주머니를 주움(`MailTaken=1`).

## 교차검증 (Codex + Claude 검토자, 1회씩)

- Codex: P1 1건(줍기 보고가 한 번 거절되면 그 주머니를 다시 못 알림), P2 2건(카우보이 없이 지나친 크레인이 우편 수에 섞임, 놓침 재시작
  지점이 앞 다리와 겹침), P3 2건. Claude 검토자: P1 1건(재시작 지점 — 같은 문제), P2 2건(같은 두 문제), P3 여러 건.
- 고친 것:
  - 재시작 지점 → 크레인 앞 다리의 재시작 지점(`bridgeAt(index) − RestartLead`).
  - 다시 알리기 → 1초 뒤나 달리기가 바뀐 뒤 다시, 서버는 놓침 판정 직전까지 받음.
  - 우편 수 → 실제로 주운 수만 따로 셈.
  - 주머니 위치(가운데·판자 통로에서는 안 닿게: 3.4·11.1·1.6), 기둥을 납작한 기관차에서 떨어뜨림(5.4), 크레인 치수를 Config로,
    흩어진 기차 속성 읽기를 `TrainState`로 모음, 주석·오타.
- Codex 재확인(1회): 세 건 모두 바르게 고쳐졌고 새 P1·P2 없음.
- 남긴 P3: "우편!"은 서버 확인 전에 뜬다(거절되면 곧 놓침으로 이어짐), 카우보이가 중간에 들어올 때 이미 옆에 온 주머니는 곧 놓침.
