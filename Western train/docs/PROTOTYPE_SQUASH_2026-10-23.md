## 무엇이 들어갔나

플레이어가 들어오면 자기 아바타(머리·몸·클래식 옷, 액세서리 없음)가 등을 대고 누운 얼굴 기관차가 되어 자기 선로 칸에 선다.
S(모바일 "납작" 버튼, 게임패드 B)를 누르고 있으면 만화처럼 납작해지고, 떼면 "뽀용" 하고 위로 늘었다가 출렁이며 돌아온다.
누를 때와 뗄 때 굴뚝 캡 양옆으로 증기가 한 번씩 뿜어진다. 배경 흐름·장애물·판정·점프·카우보이·소리는 아직 없다.

## 납작이 움직이는 방식

- 기관차 공간: X 오른쪽, Y 위, Z 뒤(앞은 -Z), 원점은 가운데 아래 선로 위. 서버는 부품마다 `RestCFrame`·`RestSize`·
  `RestAnchor`·`SquashExponent`(FileMesh면 `RestMeshScale`)를 `Base` 부품 기준으로 저장하고, 만든 뒤에는 건드리지 않는다.
- 클라이언트는 `pose(rest, body)`로 앵커를 몸 배율로 옮기고, 앵커에서 부품 중심까지의 거리를 부품 자기 배율(높이만
  `body.y ^ exponent`)로 늘인다. 굴뚝·캡은 앵커가 굴뚝 발이고 지수 1.8이라 몸보다 더 세게 접힌다.
- 크기는 부품 자기 축이 기관차 공간에서 얼마나 늘었는지(`stretchOf`)로 계산한다. 누운 몸통은 자기 Y가 앞뒤, 자기 Z가 위아래다.
- 스프링: 누를 때 24 rad/s·감쇠 0.6, 뗄 때 18 rad/s·감쇠 0.32(넘쳐서 "뽀용"). 값 범위 -0.6~1.4.

  `python -I tools/lint/run_lint.py` — 새 지적 0건.

- 입력: `user_keyboard_input`(Client)으로 S `keyDown`/`keyUp`. 증기 캡처는 QA 때만 클라이언트에서 증기 `ParticleEmitter.TimeScale = 0.04`로 늦췄다(코드에는 없음).

## 결과

- 기관차가 만들어지고 얼굴(머리)이 맨 앞에서 앞을 본다. 시험 계정의 클래식 셔츠·바지가 늘어난 몸에 그대로 그려진다
  (`Shirt`, `Pants` 확인). 액세서리를 뺐으므로 머리카락이 없다(DESIGN 열린 질문).
- 누르면 머리가 납작한 원판, 굴뚝·캡이 낮은 원판, 몸이 바닥에 깔린다. 뗄 때 머리 높이 기록: 0.40 → 1.20(20% 넘침) → 0.93 → 1.02
  → 약 0.6초 만에 1.00. 누를 때는 0.36까지 살짝 넘쳤다가 0.25초 안에 0.40.
- 리스폰 뒤에도 같은 모습·같은 카메라. 콘솔 오류 없음.
- 원통 한계(검토자 둘 다 지적): Roblox 원통은 Y·Z 중 작은 값이 지름이라, 납작할 때 바퀴·허브가 40% 크기의 작은 원이 된다
  (아랫면은 선로에 붙어 있음). 굴뚝·캡은 폭 1.3이 아니라 1.08배만 넓어진다. 연출로 괜찮은지는 오너 판단, 최종 아트는 MeshPart 바퀴로.
- 증기: 누르는 순간 캡이 아직 높이 있을 때 뿜어서, 기관차가 내려앉은 뒤 증기가 공중에 남는다(만화 같은 느낌으로 둠).

## Studio에서 고친 것

- **굴뚝이 몸통 위에 떠 있음 → `ChimneySink` 0.8:** 몸통 메시는 상자보다 둥글어서 굴뚝 발(상자 윗면)과 가슴 사이에 틈이 보였다.
  굴뚝을 보일러 안으로 0.8 더 내려 보이는 높이는 같게 했다. 납작할 때도 발이 몸 안에 있다.
- **첫 접속 때 카메라가 기관차 바로 뒤에서 38 거리 → 시작 시점 붙잡기 + 거리 26:** Roblox 기본 카메라는 캐릭터가 들어오면 그 캐릭터
  루트가 보는 방향 뒤로 돌아간다(-15도, 기록상 오프셋 (0, 9.8, 36.7)). 첫 접속에서는 이것이 기관차가 생긴 뒤에 일어나 시작 시점을
  덮어썼다(리스폰 때는 먼저 일어나서 문제없었음). `BindToRenderStep`(Camera 우선순위 + 1)으로 1.5초 동안 시작 시점을 다시 놓고,
  끝나면 최소 줌을 8로 푼다. 거리는 얼굴과 납작이 잘 보이게 38 → 26.
- **숨긴 캐릭터가 보일러 안이 아니라 스폰(0, 4, 80)에 있음 → 한 번 더 옮김:** 시험해 보니 `CharacterAdded`는 캐릭터가 Workspace에
  들어가기 전(Parent nil, 위치 0,0,0)에 불리고, 그 뒤 `LoadCharacter`가 스폰 위로 옮긴다. 그래서 핸들러 안의 `PivotTo`가 덮어써졌다.
  `task.defer`로 한 번 더 옮긴다(멈춘 숨기기는 건너뜀). 고친 뒤 첫 접속·리스폰 모두 캐릭터 위치 = 기관차 `Base`.

## Codex 재확인(1회) 뒤 고친 것

재확인에서 P1은 없고 P2 5건이 나왔다. 규칙대로 고친 뒤 재확인은 더 받지 않았고, Studio에서 직접 확인했다.

- 예약된 이전 상태가 새 기관차에 적용될 수 있음 → 입력이 바뀔 때마다 기관차가 없어도 서버에 보내고, 새 내 기관차가 오면 지금 입력
  (눌림/뗌)을 항상 보낸다. 시험: 납작한 채 기관차 추적을 끊고 S를 뗀 뒤 서버 `Squashed` = false.
- 태그를 뗐다 다시 붙이면 납작한 자세가 남음 → 애니메이터가 처음 한 번은 쉬는 자세를 그린다(`settled = false`로 시작).
  시험: 머리 비율 0.40(납작, 추적 끊김) → 다시 붙인 뒤 1.00.
- 증기 위치가 원통의 실제 테두리와 어긋남 → 캡 반지름 = `min(Size.Y, Size.Z) / 2`.
- 카메라 홀드가 끝나면 예전 줌 거리로 튐 → 홀드 동안 최소·최대 줌을 둘 다 26으로, 끝나면 최대 줌은 `StarterPlayer` 값, 최소 줌은 8.
  시험: 줌 60으로 뺀 뒤 리스폰 → 홀드 뒤 거리 26.0, 최소 8 / 최대 400.
- 생성이 끝내 실패해 `restore()`할 때 캐릭터 하체가 땅속 → 경계 상자 바닥이 선로 높이에 오게 들어 올린다. 시험: 바닥 -3.00 → 0.40.
- `CharacterAdded` 다음 위치 이동(A)의 타이밍은 정적으로 확정할 수 없다는 지적 → 지연 실행 때 아직 Parent가 없으면
  `AncestryChanged`를 기다린 뒤 옮긴다. 이 장소(Studio)의 순서는 위 기록대로 확인했고, 다른 SignalBehavior 설정에서는 시험하지 않았다.
- P3로 남김: 게임패드 여러 개가 같은 B를 누르면 KeyCode로만 구분한다. `Config`의 옛 주석은 고쳤다.
